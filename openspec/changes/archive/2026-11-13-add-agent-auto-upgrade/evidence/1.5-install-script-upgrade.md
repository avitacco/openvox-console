## What the Rocky run above found, and the fix

The rpm upgraded but `systemctl is-active` answered `inactive`: the service was left stopped and disabled.
rpm runs the old package's %postun after the new package's %post, and `postrm.sh` tore the service down on every run, upgrade or not.
Fixed in two places: `postrm.sh` now acts only on a real removal, and the rpm runs `postinst.sh` as %posttrans (end of transaction, after every %postun) instead of %post.
The second part is what repairs an upgrade *from* a package that still carries the old %postun, which is this node's case:
