Every package across the fleet, and the published advisories that affect it — checked against what your nodes actually report, not what they were meant to have.

Answer "who still has the old one"

Search by package, version or provider and see which nodes carry what, without logging into any of them. Collection is opt-in per node and the console can switch it on remotely, so you are not forced to collect everywhere to have it somewhere.

Findings, merged across sources

Point the console at the advisory sources you trust. Findings merge per vulnerability, the highest severity wins, and the page names every source reporting it — so two sources disagreeing is something you can see rather than something resolved behind your back.

Each finding carries the installed version, the fixed version where there is one, and whether a fix exists at all. That last one is the difference between work you can schedule and work you cannot.

A node with no package inventory cannot be assessed, and the console says so rather than counting it as clean. "Nothing known against it" and "never looked" are different answers and appear differently.

OpenVox Console ships as two container images, built for amd64 and arm64 on every push. SETUP.md walks through a real deployment - openvoxserver, openvoxdb, Postgres and the console - with both container and package instructions.
