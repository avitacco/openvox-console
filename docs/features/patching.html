Scan Linux nodes for the updates they are missing, and apply them in batches with a way to stop before a bad update reaches the whole fleet.

Pending updates, as each node's package manager reports them

A scan asks the node's agent to run apt, dnf or yum in a mode that changes nothing, then shows each pending update with its installed and available versions and whether the package manager calls it a security update. A node also says whether it already needs a reboot.

Scans run on a schedule you control, or on demand for one node or a whole group. A node that cannot be scanned is listed as unable to report — never shown as fully patched.

Patch in batches, with a safety stop

Choose security updates, everything, or named packages, and how many nodes to patch at once. Set how many failures end the run, so that no further batch starts once something has gone wrong. Preview with a dry run that installs nothing, and let nodes that need it reboot when they are done.

Progress is shown node by node, a node that goes quiet part-way is reported as having done so instead of hanging forever, and when it finishes the node is scanned again so the page shows what is really left.

Each node reports what its package manager would upgrade. Preview a run on the nodes you chose. Nothing is installed. Patch a few nodes at a time, stopping after as many failures as you allow. Each patched node is scanned again, so what remains is on record. Scanning and patching follow the same node group access as every other action: people can patch the nodes their roles cover, and no others. Patch runs are jobs like any other, with results per node, and show up in the job history with their options.

Windows, macOS and zypper (SUSE) nodes are not scanned. They are listed as unable to report, so a gap in coverage is visible rather than mistaken for a clean bill of health.
