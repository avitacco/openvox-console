Nodes

Node-Agenten aktuell halten

Wie die Konsole den Node-Agenten auf Ihren Nodes selbstständig aktualisiert, wie Sie sehen, welche Nodes zurückliegen, und der einmalige Schritt für Nodes, die installiert wurden, bevor es diese Funktion gab.

Der Node-Agent ist der kleine Dienst, den das Installationsskript auf jeden Node bringt. Er hält die Verbindung des Nodes zur Konsole und führt die Läufe und Tasks aus, die Sie starten. Er wird mit der Konsole gebaut und in ihr ausgeliefert, daher bringt eine neuere Konsole meist einen neueren Node-Agenten mit.

Die Konsole aktualisiert den Node-Agenten auf Ihren Nodes für Sie. Wenn sich ein Node verbindet, fragt die Konsole, welchen Build des Agenten er ausführt. Ist dieser Build älter als der, den die Konsole ausliefert, weist die Konsole den Node an, ein Upgrade durchzuführen, und der Node lädt den neuen Build von der Konsole herunter, prüft ihn, installiert ihn und startet damit neu. Sie tun auf dem Node nichts.

Was Sie sehen

  • Seite „Nodes“. Ein Node, dessen Agent zurückliegt, wird als Client veraltet markiert.
  • Die Seite eines Nodes. Zeigt die Version des Agenten und wann er gebaut wurde, ob er aktuell ist und was aus dem letzten Upgrade-Versuch geworden ist.
  • Dashboard. Unter Flottenstatus: wie viele Node-Agenten aktuell sind, wie viele veraltet, wie viele Upgrades fehlgeschlagen sind und ob automatische Upgrades eingeschaltet sind.

Ein Upgrade selbst von der Seite eines Nodes aus zu starten erfordert nodes:manage auf einer Rolle, deren Node-Gruppen den Node einschließen. Die Upgrades, die die Konsole selbst startet, sind nicht durch die Node-Gruppen irgendeiner Person begrenzt.

Ein Node, der sich seit dem Upgrade der Konsole nicht verbunden hat, wird als noch nicht gemeldet angezeigt, nicht als veraltet. Er meldet sich bei der nächsten Verbindung.

Nodes, die installiert wurden, bevor es automatische Upgrades gab

Ein Node-Agent aus der Zeit vor dieser Funktion kann sich nicht selbst aktualisieren, weil er die Anfrage nicht versteht. Die Konsole zeigt einen solchen Node als veraltet an, mit dem Hinweis, dass das Installationsskript erneut ausgeführt werden muss. Führen Sie es einmal auf dem Node aus, genau wie beim Hinzufügen des Nodes:

Linuxcurl -fsSL https://console.example.com/packages/install.sh | sudo bash macOScurl -fsSL https://console.example.com/packages/install-macos.sh | sudo bash WindowsInvoke-WebRequest https://console.example.com/packages/install.ps1 -OutFile install.ps1 .\install.ps1

Ab dann hält sich der Node selbst aktuell. Das Dashboard zählt die Nodes, die noch darauf warten, sodass Sie erkennen, wann Sie alle erledigt haben.

Verwalten Sie das Linux-Paket stattdessen mit Puppet, erfüllt ensure => latest für das Paket node-agent-client aus dem Repository der Konsole denselben Zweck.

Was ein Upgrade tut und was nicht

  • Es unterbricht nie laufende Arbeit. Ein Node, der sich mitten in einem Lauf oder Task befindet, wird in Ruhe gelassen und eine Minute später erneut versucht.
  • Es wird vor der Installation geprüft. Die Konsole sendet die erwartete Prüfsumme des Downloads über die authentifizierte Verbindung des Nodes. Der Node lehnt alles ab, was nicht passt, und startet den neuen Agenten einmal, um zu bestätigen, dass er funktioniert, bevor er den alten ersetzt. Schlägt eine der beiden Prüfungen fehl, behält der Node seinen bisherigen Agenten.
  • Es geht jeweils nur ein paar Nodes gleichzeitig. Höchstens 20 Nodes führen gleichzeitig ein Upgrade durch, egal wie viele zurückliegen.
  • Es geht nur vorwärts. Ein Node mit einem neueren Agenten als dem, den die Konsole ausliefert, wird in Ruhe gelassen. Das sehen Sie mitten im Upgrade eines Clusters von Konsoleninstanzen oder nach dem Zurückrollen der Konsole.
  • Unter Linux läuft es über den Paketmanager. Der Node installiert das .deb oder .rpm der Konsole, sodass dpkg und rpm die tatsächlich installierte Version anzeigen.

Upgrades unter macOS und Windows werden von den Tests des Projekts abgedeckt, wurden aber noch nicht vollständig auf echten macOS- und Windows-Hosts durchlaufen. Melden Sie alles, was nicht wie hier beschrieben abläuft.

Wenn ein Upgrade fehlschlägt

Die Seite des Nodes zeigt den Grund, in den eigenen Worten des Nodes: Der Download ist fehlgeschlagen, die Prüfsumme stimmte nicht, der Paketmanager war beschäftigt. Die Konsole versucht es nach fünf Minuten erneut, wartet dann jedes Mal doppelt so lange und hört nach fünf Fehlschlägen beim selben Build auf.

Die häufigste Ursache ist ein Node, der die Basis-URL der Konsole (CONSOLE_BASE_URL) nicht erreichen kann, von der er den neuen Agenten herunterlädt. Das Installationsskript hat dieselbe Adresse verwendet; prüfen Sie also, was sich seit der Installation des Nodes geändert hat.

Sobald Sie die Ursache behoben haben, wählen Sie auf der Seite des Nodes Client aktualisieren, um es sofort erneut zu versuchen. Das erfordert die Berechtigung nodes:manage und einen verbundenen Node. Es funktioniert unabhängig davon, ob automatische Upgrades eingeschaltet sind, und auch nachdem die automatischen Versuche aufgehört haben.

Die Konsole startet außerdem von selbst neu, wenn Sie sie auf eine Version aktualisieren, die einen anderen Node-Agenten ausliefert.

Automatische Upgrades ausschalten

Damit die Konsole Node-Agenten nicht mehr selbstständig aktualisiert, setzen Sie dies auf jeder Konsoleninstanz und starten Sie sie neu:

CONSOLE_AGENT_AUTO_UPGRADE=false

Die Konsole verzeichnet weiterhin den Agent-Build jedes Nodes und zeigt weiterhin, welche Nodes veraltet sind. Client aktualisieren auf der Seite eines Nodes funktioniert weiterhin.

Um stattdessen einen einzelnen Node auszunehmen, setzen Sie für den Node-Agenten auf diesem Node NODE_AGENT_ACCEPT_UPGRADES=false und starten ihn neu:

Plattform Wo es gesetzt wird
Linux Fügen Sie die Zeile zu /etc/node-agent-client/local.env hinzu und führen Sie dann sudo systemctl restart node-agent-client aus
Windows Setzen Sie sie als System-Umgebungsvariable und starten Sie dann den Dienst node-agent-client neu
macOS Fügen Sie sie EnvironmentVariables in /Library/LaunchDaemons/org.voxpupuli.node-agent-client.plist hinzu und laden Sie den Job dann neu

Die Seite des Nodes meldet dann, dass Upgrades auf diesem Node abgelehnt werden, und die Konsole versucht es nicht. Unter macOS überschreibt ein erneutes Ausführen des Installationsskripts diese Datei; setzen Sie den Wert danach also erneut.
