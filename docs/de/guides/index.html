Schritt für Schritt: Installieren Sie die Konsole, fügen Sie Ihre Nodes hinzu, skalieren Sie sie und betreiben Sie sie im Alltag. Jeder Befehl wird genau so gezeigt, wie Sie ihn eingeben.

Installation

Was Sie aufbauen, welche Namen Sie vor dem Start klären müssen und welcher Installationsanleitung Sie folgen.

Betreiben Sie openvoxserver, openvoxdb, beide Datenbanken und die Konsole mit Docker Compose – vom leeren Host bis zu einer Konsole, die bereit für Nodes ist.

Installieren Sie openvoxserver, openvoxdb und Postgres aus Paketen, bauen Sie die Konsole und betreiben Sie sie als systemd-Dienst.

Nodes

Registrieren Sie einen Node mit einem einzigen Skript unter Linux, macOS oder Windows, signieren Sie sein Zertifikat und beobachten Sie, wie er sich verbindet und läuft.

Node-Zertifikate aus der Konsole signieren, widerrufen und bereinigen, und was jede Aktion mit einem verbundenen Node macht.

Einen Node aus der Konsole löschen, was das in openvoxdb und der CA bewirkt und was erhalten bleibt.

Wie die Konsole den Node-Agenten auf Ihren Nodes selbstständig aktualisiert, wie Sie sehen, welche Nodes zurückliegen, und der einmalige Schritt für Nodes, die installiert wurden, bevor es diese Funktion gab.

Skalierung

Was jeder Betriebsmodus der Konsole bedient und betreibt und was jeder davon an Konfiguration braucht.

Clustern Sie eine zweite Konsoleninstanz, teilen Sie Instanzen in Betriebsmodi auf und platzieren Sie die Klassifizierung neben den Compilern.

Nutzung

Legen Sie fest, welche Klassen, Parameter und welches Environment jeder Node erhält, mit einem Baum aus Node-Gruppen, die per Facts zutreffen oder per Namen fest zugewiesen werden.

Deployen Sie Puppet-Code aus einem oder mehreren Control-Repositories in die Environments, aus denen openvoxserver kompiliert.

Führen Sie Puppet oder einen Puppet-Task auf Abruf auf einem Node, einer Auswahl, den Nodes, auf die eine Abfrage zutrifft, oder einer Node-Gruppe aus und sehen Sie, was jeder Node getan hat.

Erstellen Sie einen Plan – eine Liste von Puppet-Läufen und Tasks, die der Reihe nach ausgeführt werden –, bewahren Sie ihn auf, führen Sie ihn auf den Nodes Ihrer Wahl aus und verfolgen Sie jeden Schritt.

Speichern Sie einen Puppet-Lauf, einen Task oder einen Plan, um ihn später zu starten, einmal oder wiederholt, auf Nodes, die bei jedem Start neu ermittelt werden.

Gewähren Sie Personen Zugriff über Rollen und Berechtigungen, melden Sie sich über Ihren Identitätsanbieter an und stellen Sie Tokens für Programme aus.

Richten Sie Anbieter für Sicherheitslücken ein, lesen Sie die Befunde für die Flotte und erfahren Sie, was jeder Anbieter sehen kann und was nicht.

Scannen Sie Linux-Nodes auf ausstehende Paket-Updates und patchen Sie sie dann in Stapeln, mit Testlauf, Stopp-Schwellenwert und optionalem Neustart.

Registrieren Sie Hosts, die die Konsole per SSH erreicht, heften Sie ihre Hostschlüssel an, prüfen Sie sie und führen Sie Tasks auf ihnen aus wie auf jedem anderen Node.

Führen Sie YAML-Pläne aus, die in Ihren Modulen liegen, mit typisierten Parametern, zwischen Schritten weitergegebenen Ergebnissen und jedem Task gegen Ihre Node-Gruppen geprüft.

Geben Sie einem KI-Agenten ein eigenes, eingeschränktes Token, lassen Sie ihn die Flotte lesen und Änderungen anfordern, und genehmigen Sie jede Änderung selbst, bevor irgendetwas läuft.

Betrieb

Erholen Sie sich vom Verlust der Datenbank der Konsole, indem Sie einen Streaming-Replication-Standby hochstufen.

Ersetzen Sie den Schlüssel, mit dem die Konsole Login-Tokens signiert, ohne jemanden abzumelden.

Überführen Sie die beiden Datenbanken einer Container-Installation von Postgres 17 auf 18, indem Sie sie sichern und wiederherstellen.

OpenVox Console wird als Container-Images ausgeliefert, bei jedem Push für amd64 und arm64 gebaut, sowie als einzelnes Binary. Die Installationsanleitungen führen Sie vom leeren Host zu einer funktionierenden Installation – openvoxserver, openvoxdb, Postgres und die Konsole – mit Containern oder mit Paketen.
