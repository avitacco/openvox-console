Die Container-Datenbanken auf Postgres 18 aktualisieren

Überführen Sie die beiden Datenbanken einer Container-Installation von Postgres 17 auf 18, indem Sie sie sichern und wiederherstellen.

Die Produktions-Compose-Datei betreibt beide Datenbanken auf Postgres 18. Postgres-18-Images legen ihre Daten in einem nach der Version benannten Verzeichnis innerhalb des Volumes ab, daher werden die Volumes unter /var/lib/postgresql eingebunden, nicht wie bisher unter /var/lib/postgresql/data.

Ein Postgres-18-Container, der gegen ein Volume mit noch Postgres-17-Daten gestartet wird, verweigert den Start mit einem Fehler, der mit Error: in 18+, these Docker images are configured to store database data in a format which is compatible with "pg_ctlcluster" beginnt. Das ist eine Verweigerung, kein Schaden: Die alten Daten bleiben unberührt. Diese Anleitung überführt sie.

Das Upgrade ist ein Sichern und Wiederherstellen: pg_upgrade bräuchte beide Versionen in einem Image, und diese Images enthalten nur eine.

Beide Datenbanken sichern

Tun Sie dies, während die Postgres-17-Container noch laufen. Stoppen Sie, was in sie schreibt, und lassen Sie die Datenbanken laufen:

docker compose -f docker-compose.yml stop console openvoxdb docker compose -f docker-compose.yml exec -T openvoxdb-postgres \ pg_dumpall -U openvoxdb > openvoxdb-17.sql docker compose -f docker-compose.yml exec -T console-postgres \ pg_dumpall -U console > console-17.sql

Prüfen Sie vor dem Weitermachen, ob beide Dateien vorhanden und nicht leer sind:

ls -l openvoxdb-17.sql console-17.sql

Die Volumes ersetzen

Dies löscht die Postgres-17-Daten. Ab hier sind die beiden Sicherungsdateien die einzige Kopie, weshalb die obige Prüfung zuerst kommt.

 docker compose -f docker-compose.yml down docker volume rm openvox-console_openvoxdb-postgres-data openvox-console_console-postgres-data

Die Volume-Namen richten sich nach dem Namen des Projektverzeichnisses; prüfen Sie sie mit docker volume ls.

Auf Postgres 18 wiederherstellen

Starten Sie nur die Datenbanken. Sie starten leer, und die von openvoxdb erhält die benötigte pg_trgm-Erweiterung aus der Compose-Datei:

docker compose -f docker-compose.yml up -d openvoxdb-postgres console-postgres docker compose -f docker-compose.yml exec -T openvoxdb-postgres \ psql -U openvoxdb < openvoxdb-17.sql docker compose -f docker-compose.yml exec -T console-postgres \ psql -U console < console-17.sql

Starten Sie dann alles Übrige:

docker compose -f docker-compose.yml up -d

Wenn openvoxdb meldet, dass pg_trgm fehlt

openvoxdb verweigert den Start ohne die Erweiterung pg_trgm. Die Compose-Datei fügt sie nur beim ersten Anlegen der Datenbank hinzu, daher muss sie bei einer bereits vorhandenen Datenbank von Hand hinzugefügt werden:

docker compose -f docker-compose.yml exec openvoxdb-postgres \ psql -U openvoxdb -c 'CREATE EXTENSION IF NOT EXISTS pg_trgm;'

Bei Postgres 17 bleiben

Bei 17 zu bleiben erfordert zwei Änderungen, nicht eine: Setzen Sie OPENVOXDB_POSTGRES_VERSION=17-alpine (und das Gegenstück der Konsole, CONSOLE_POSTGRES_VERSION), und verlegen Sie den Mount jedes Volumes zurück nach /var/lib/postgresql/data. Nur die Version zu ändern führt zu dem oben genannten Fehler.
