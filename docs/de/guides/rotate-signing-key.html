Betrieb

Den Token-Signaturschlüssel rotieren

Ersetzen Sie den Schlüssel, mit dem die Konsole Login-Tokens signiert, ohne jemanden abzumelden.

Die Konsole signiert ihre Login-Tokens mit ihrem eigenen ES256-Schlüssel. Jedes Token nennt den Schlüssel, der es signiert hat, und die Konsole prüft Tokens gegen eine Menge von Schlüsseln. So kann ein neuer Schlüssel das Signieren übernehmen, während mit dem alten signierte Tokens bis zu ihrem Ablauf weiter funktionieren: Niemand wird abgemeldet, und nichts steht still.

Drei Einstellungen sind beteiligt:

Einstellung Was es ist
CONSOLE_RBAC_SIGNING_KEY_FILE der Schlüssel, mit dem diese Instanz signiert
CONSOLE_RBAC_SIGNING_KEY_ID die ID des Schlüssels, die in jedes von ihm signierte Token geschrieben wird. Nicht gesetzt ist sie default
CONSOLE_RBAC_VERIFICATION_KEYS_DIR ein Verzeichnis weiterer Schlüssel, deren Tokens akzeptiert werden, eine Datei pro Schlüssel, benannt <key ID>.pem

Eine Instanz akzeptiert immer Tokens, die mit ihrem eigenen Signaturschlüssel signiert sind.

Den neuen Schlüssel erzeugen

Wählen Sie eine ID dafür; ein Datum eignet sich gut:

openssl ecparam -genkey -name prime256v1 -noout -out 2026-10-01.pem

Jede Instanz beide Schlüssel akzeptieren lassen

Legen Sie auf jeder Konsoleninstanz den aktuellen und den neuen Schlüssel in ihr Verifizierungsverzeichnis, jeweils nach seiner ID benannt. Eine Installation, die CONSOLE_RBAC_SIGNING_KEY_ID nie gesetzt hat, verwendet default für den aktuellen Schlüssel:

sudo install -d -m 0750 -o root -g openvox-console /etc/openvox-console/rbac-verification-keys sudo install -m 0640 -o root -g openvox-console \ /etc/openvox-console/rbac-signing-key.pem /etc/openvox-console/rbac-verification-keys/default.pem sudo install -m 0640 -o root -g openvox-console \ 2026-10-01.pem /etc/openvox-console/rbac-verification-keys/2026-10-01.pem

Setzen Sie CONSOLE_RBAC_VERIFICATION_KEYS_DIR auf dieses Verzeichnis, falls noch nicht geschehen, und starten Sie jede Instanz neu.

Dies überall zu tun, bevor irgendetwas mit dem neuen Schlüssel signiert, hält eine lastverteilte Installation funktionsfähig: Ein Token, das eine Instanz mit dem neuen Schlüssel signiert, wird dann von jeder anderen akzeptiert.

Mit dem neuen Schlüssel signieren

Lassen Sie die Instanzen, die Tokens ausstellen (all und web), mit dem neuen Schlüssel unter seiner ID signieren und starten Sie sie neu:

CONSOLE_RBAC_SIGNING_KEY_FILE=/etc/openvox-console/rbac-verification-keys/2026-10-01.pem CONSOLE_RBAC_SIGNING_KEY_ID=2026-10-01

Neue Anmeldungen erhalten nun Tokens, die mit dem neuen Schlüssel signiert sind. Mit dem alten signierte Tokens funktionieren weiterhin, weil jede Instanz ihn noch akzeptiert.

Den alten Schlüssel ausmustern

Ein Token lebt höchstens 24 Stunden: So lange gilt ein Refresh-Token. Sobald 24 Stunden vergangen sind, seit die letzte Instanz begonnen hat, mit dem neuen Schlüssel zu signieren, entfernen Sie die Datei des alten Schlüssels aus dem Verifizierungsverzeichnis jeder Instanz und starten Sie sie neu. Mit dem alten Schlüssel signierte Tokens werden ab dann abgelehnt.

Den alten Schlüssel früher zu entfernen meldet alle ab, deren Tokens er signiert hat. Ihn zu entfernen und dann den neuen Schlüssel zu verlieren meldet alle ab. Sichern Sie den neuen Schlüssel, bevor Sie den alten ausmustern.
