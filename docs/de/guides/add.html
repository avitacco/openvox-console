Nodes

Nodes hinzufügen

Registrieren Sie einen Node mit einem einzigen Skript unter Linux, macOS oder Windows, signieren Sie sein Zertifikat und beobachten Sie, wie er sich verbindet und läuft.

Einen Node hinzuzufügen ist ein einziges Skript, das einmal auf dem Node ausgeführt wird. Es installiert den OpenVox-Agenten, registriert den Node bei der CA, falls er noch kein Zertifikat hat, installiert den Node-Agenten der Konsole aus dem eigenen Paket-Repository der Konsole und startet ihn als Dienst. Es kann gefahrlos erneut ausgeführt werden.

Bevor Sie beginnen

Die Konsole muss zwei Adressen kennen, die ein Node verwenden wird; beide wurden bei ihrer Installation gesetzt:

  • CONSOLE_NODE_TRANSPORT_PUBLIC_ADDR, die Adresse, die Nodes anwählen, um ihre Verbindung zur Konsole offen zu halten. Ihr Host muss im Zertifikat des Node-Transports stehen.
  • CONSOLE_PUPPET_SERVER_PUBLIC_ADDR, der Puppet-Server, bei dem sich ein Node registriert. Er muss ein Name im Zertifikat von openvoxserver sein. Ist er nicht gesetzt, lässt das Skript die Puppet-Server-Konfiguration des Nodes unverändert, was zu Nodes passt, die bereits auf anderem Weg auf einen Server zeigen.

Jeder Node muss die Basis-URL der Konsole, openvoxserver auf Port 8140 und die Adresse des Node-Transports erreichen können.

Das veröffentlichte Konsolen-Image enthält bereits die Node-Agent-Pakete, die das Skript installiert. Wenn Sie die Konsole selbst gebaut haben, bauen Sie diese vor der Konsole, wie es die Paket-Installationsanleitung beschreibt, sonst schlägt jede Node-Installation mit einem 404 fehl.

Das Installationsskript ausführen

Auf dem Node, als Administrator:

Linuxcurl -fsSL https://console.example.com/packages/install.sh | sudo bash macOScurl -fsSL https://console.example.com/packages/install-macos.sh | sudo bash WindowsInvoke-WebRequest https://console.example.com/packages/install.ps1 -OutFile install.ps1 .\install.ps1

Führen Sie PowerShell unter Windows als Administrator aus.

Die Skripte für macOS und Windows werden von den Tests des Projekts geprüft, wurden aber noch nicht, wie das Linux-Skript, vollständig auf echten macOS- und Windows-Hosts durchlaufen. Melden Sie alles, was nicht wie hier beschrieben abläuft.

Das Zertifikat des Nodes signieren

Signiert die CA Anfragen automatisch, endet das Skript von selbst. Andernfalls wartet es bis zu fünf Minuten und prüft alle 15 Sekunden. Signieren Sie die Anfrage, während es wartet, und derselbe Lauf geht bis zum Ende weiter:

  1. Öffnen Sie die Seite Nodes der Konsole. Der Node wird mit einer ausstehenden Zertifikatsanfrage aufgeführt.
  2. Wählen Sie Signieren.

Das Signieren aus der Konsole erfordert die Zertifikatsadministrator-Berechtigung und einen Benutzer mit der Berechtigung nodes:certs:manage; siehe Node-Zertifikate verwalten. Sie können auch direkt auf dem CA-Host signieren:

sudo /opt/puppetlabs/bin/puppetserver ca sign --certname <node certname>

Das Skript endet auf eine von drei Arten:

Was geschehen ist Was Sie sehen
Die Anfrage wurde während des Wartens signiert Es läuft weiter und schließt die Installation ab
Die Wartezeit lief ab, während die Anfrage noch unsigniert war Es bricht ab und nennt die Seite „Nodes“, auf der zu signieren ist; signieren Sie dort und führen Sie das Skript dann erneut aus
Es konnte die CA nicht erreichen Es bricht ab und meldet ein Verbindungs- oder TLS-Problem – keine ausstehende Anfrage

Eine nicht erreichbare CA wird erst gemeldet, wenn die volle Wartezeit verstrichen ist, weil der Agent es weiter versucht, falls das Problem nur kurz ist. Wenn Sie einen Verbindungsfehler sehen, prüfen Sie die Namensauflösung und Port 8140, statt nach einer zu signierenden Anfrage zu suchen.

Den Node beim Verbinden beobachten

Auf der Seite Nodes erscheint der Node als verbunden, mit einem signierten Zertifikat.

Ein Node, der sich verbindet, bevor er jemals an openvoxdb gemeldet hat, würde sonst bis zu seinem nächsten geplanten Puppet-Lauf leer dastehen. Die Konsole startet deshalb sofort seinen ersten Lauf. Dieser Lauf erscheint wie jeder andere auf der Seite Jobs, als gestartet von system:initial-run verzeichnet. Sobald er abgeschlossen ist, zeigt die Seite des Nodes seine Facts, seine Reports und die ihm zugewiesenen Klassen.

Danach kümmert sich der Node-Agent um sich selbst

Um den Node-Agenten zu aktualisieren, führen Sie das Skript nicht erneut aus. Wenn Sie die Konsole aktualisieren, aktualisiert sie den Node-Agenten auf jedem verbundenen Node für Sie; siehe Node-Agenten aktuell halten.

Die Pakete des Nodes melden (optional)

Das Paketinventar ist für jeden Node ausgeschaltet, bis Sie es einschalten. Schalten Sie auf der Seite des Nodes im Abschnitt Pakete das Melden ein. Die Konsole weist den Node an, den Paket-Fact hinzuzufügen, und führt sofort Puppet aus, sodass das Inventar innerhalb dieses Laufs erscheint statt erst beim nächsten geplanten. Das Ausschalten entfernt den Fact auf dieselbe Weise.

Der Schalter erfordert die Berechtigung orchestrator:run und funktioniert nur, solange der Node verbunden ist: Er wirkt sofort auf den Node, statt eine Änderung für später einzureihen.
