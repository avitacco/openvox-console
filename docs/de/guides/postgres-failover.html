Betrieb

Auf eine Standby-Datenbank umschalten

Erholen Sie sich vom Verlust der Datenbank der Konsole, indem Sie einen Streaming-Replication-Standby hochstufen.

Die Konsole hält alles Dauerhafte in ihrer Postgres-Datenbank, und in der Konsole selbst muss nichts wiederhergestellt werden. Der Verlust der primären Datenbank wird daher behoben, indem ein Standby hochgestuft und die Konsole darauf gerichtet wird. Dieses Runbook setzt einen Standby voraus, der durch die eigene Streaming Replication von Postgres aktuell gehalten wird.

Den Standby prüfen, bevor Sie ihn brauchen

Auf dem Standby:

psql -U console -d console -c "SELECT pg_is_in_recovery();"

Die Antwort ist t: Sie ist noch ein Replikat. Ein Schreibzugriff darauf wird mit cannot execute INSERT in a read-only transaction abgelehnt, was auch ein gesundes Replikat tut.

Den Standby hochstufen

psql -U console -d console -c "SELECT pg_promote();"

Innerhalb weniger Sekunden antwortet pg_is_in_recovery() mit f: Der Standby ist nun eine unabhängige, beschreibbare Datenbank.

Die hochgestufte Datenbank nimmt die Replikation vom alten Primary nicht wieder auf, falls dieser zurückkehrt. Betrachten Sie den alten Primary ab diesem Punkt als ausgemustert. Um wieder einen Standby zu haben, bauen Sie den alten Primary mit pg_basebackup -R als neuen Standby der hochgestuften Datenbank neu auf.

Die Konsole darauf richten

Ändern Sie CONSOLE_POSTGRES_DSN auf die Adresse der hochgestuften Datenbank und starten Sie die Konsole neu. Die Konsole öffnet ihre Verbindungen einmalig beim Start, daher ist ein Neustart erforderlich. Bei mehreren Instanzen starten Sie jede neu.

Ein Connection-Pooler oder Proxy vor der Datenbank gibt der Konsole eine Adresse, die ein Failover übersteht. Dann wird nur der Proxy umgestellt, und die Konfiguration der Konsole ändert sich nie.

Prüfen, ob sich die Konsole erholt hat

/health meldet Postgres wieder als ok. Melden Sie sich dann an: Das schreibt in die Datenbank und beweist damit, dass Schreibzugriffe funktionieren, nicht nur Lesezugriffe.
