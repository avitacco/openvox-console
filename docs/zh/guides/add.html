Nodes

添加 Nodes

在 Linux、macOS 或 Windows 上用一个脚本注册 Node，为其证书签名，并看到它连接和运行。

添加 Node 只需一个脚本，在 Node 上运行一次即可。它会安装 OpenVox 代理；如果该 Node 还没有证书，就向 CA 注册；从控制台自己的软件包仓库安装控制台的 Node 代理，并将其作为服务启动。重复运行也是安全的。

开始之前

控制台需要知道 Node 将使用的两个地址，二者都在安装时设置：

  • CONSOLE_NODE_TRANSPORT_PUBLIC_ADDR，即 Nodes 为保持与控制台的连接而拨号的地址。其主机部分必须包含在 Node 传输证书中。
  • CONSOLE_PUPPET_SERVER_PUBLIC_ADDR，即 Node 注册时所针对的 Puppet 服务器。它必须是 openvoxserver 证书中的某个名称。如果未设置，脚本不会改动 Node 的 Puppet 服务器配置，这适合那些已经通过其他方式指向某台服务器的 Nodes。

每个 Node 都必须能够访问控制台的基础 URL、8140 端口上的 openvoxserver 以及 Node 传输地址。

已发布的控制台镜像已经包含了脚本要安装的 Node 代理软件包。如果你自己构建控制台，请按照软件包安装指南所述，在构建控制台之前先构建它们，否则每次 Node 安装都会以 404 失败。

运行安装脚本

在 Node 上，以管理员身份执行：

Linuxcurl -fsSL https://console.example.com/packages/install.sh | sudo bash macOScurl -fsSL https://console.example.com/packages/install-macos.sh | sudo bash WindowsInvoke-WebRequest https://console.example.com/packages/install.ps1 -OutFile install.ps1 .\install.ps1

在 Windows 上，请以管理员身份运行 PowerShell。

macOS 和 Windows 脚本已通过项目测试的检查，但还没有像 Linux 脚本那样在真实的 macOS 和 Windows 主机上完整地端到端运行过。如有任何与此处描述不符的情况，请反馈。

为 Node 的证书签名

如果 CA 自动签发请求，脚本会自行完成。否则，它最多等待五分钟，每 15 秒检查一次。在它等待期间为请求签名，同一次运行就会继续执行到结束：

  1. 打开控制台的 Nodes 页面。该 Node 会出现在列表中，并带有一个待处理的证书请求。
  2. 选择签名。

从控制台签名需要证书管理员凭据，以及一个拥有 nodes:certs:manage 权限的用户；参见管理 Node 证书。你也可以直接在 CA 主机上签名：

sudo /opt/puppetlabs/bin/puppetserver ca sign --certname <node certname>

脚本会以以下三种方式之一结束：

发生了什么 你会看到什么
请求在等待期间被签名 它会继续并完成安装
等待超时，请求仍未签名 它会停止，并指明到 Nodes 页面去签名；签名后再次运行脚本
它无法访问 CA 它会停止，并报告连接或 TLS 问题——而不是待处理的请求

CA 无法访问的情况要等完整的等待时间过去后才会报告，因为代理会不断重试，以防问题只是短暂的。如果看到连接错误，请检查名称解析和 8140 端口，而不是去找待签名的请求。

查看 Node 连接

在 Nodes 页面上，该 Node 显示为已连接，并持有已签名的证书。

如果一个 Node 在从未向 openvoxdb 上报过的情况下就建立了连接，它本会一直空着，直到下一次计划内的 Puppet 运行，因此控制台会立即为它启动首次运行。该运行会像其他运行一样出现在 Jobs 页面上，记录为由 system:initial-run 启动。完成后，该 Node 的页面会显示它的 Facts、Reports 以及应用于它的类。

此后，Node 代理会自行照管

升级 Node 代理时无需再次运行脚本。当你升级控制台时，它会替你升级每个已连接 Node 上的 Node 代理；参见保持 Node 代理为最新。

上报 Node 的软件包（可选）

每个 Node 的软件包清单默认关闭，直到你开启它。在该 Node 的页面上，于其软件包部分打开上报。控制台会通知该 Node 添加软件包 Fact，并立即运行 Puppet，因此清单会在这次运行中出现，而不必等到下一次计划运行。关闭上报时，也会以同样的方式删除该 Fact。

该开关需要 orchestrator:run 权限，并且只在 Node 已连接时有效：它会当场对该 Node 执行操作，而不是把更改排队留待以后。

开始之前 运行安装脚本 为 Node 的证书签名 查看 Node 连接 此后，Node 代理会自行照管 上报 Node 的软件包（可选）

OpenVox Console 以容器镜像形式发布，每次 push 都会构建 amd64 和 arm64 版本，同时也提供单个二进制文件。安装指南将带你从一台空主机走到一套可用的部署——openvoxserver、openvoxdb、Postgres 和控制台——可以用容器，也可以用软件包。
