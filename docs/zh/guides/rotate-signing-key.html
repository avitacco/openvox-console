运维

轮换令牌签名密钥

在不让任何人退出登录的情况下，替换控制台用于签名登录令牌的密钥。

控制台使用自己的 ES256 密钥为登录令牌签名。每个令牌都注明了为其签名的密钥，而控制台会依据一组密钥来校验令牌。因此，新密钥可以接管签名工作，而旧密钥签名的令牌在过期之前依然有效：没有人会被登出，也不会有任何中断。

涉及三项设置：

设置 说明
CONSOLE_RBAC_SIGNING_KEY_FILE 此实例用于签名的密钥
CONSOLE_RBAC_SIGNING_KEY_ID 密钥的 ID，会写入它签名的每个令牌。未设置时为 default
CONSOLE_RBAC_VERIFICATION_KEYS_DIR 一个存放其他可接受令牌的密钥的目录，每个密钥一个文件，命名为 <key ID>.pem

实例总是接受用其自身签名密钥签名的令牌。

生成新密钥

为它选择一个 ID；日期就是个不错的选择：

openssl ecparam -genkey -name prime256v1 -noout -out 2026-10-01.pem

让每个实例同时接受两个密钥

在每个控制台实例上，把当前密钥和新密钥都放入其验证目录，各自以其 ID 命名。从未设置过 CONSOLE_RBAC_SIGNING_KEY_ID 的部署，当前密钥使用 default：

sudo install -d -m 0750 -o root -g openvox-console /etc/openvox-console/rbac-verification-keys sudo install -m 0640 -o root -g openvox-console \ /etc/openvox-console/rbac-signing-key.pem /etc/openvox-console/rbac-verification-keys/default.pem sudo install -m 0640 -o root -g openvox-console \ 2026-10-01.pem /etc/openvox-console/rbac-verification-keys/2026-10-01.pem

如果尚未设置，请将 CONSOLE_RBAC_VERIFICATION_KEYS_DIR 设置为该目录，然后重启每个实例。

在任何实例用新密钥签名之前先在所有地方完成这一步，才能确保负载均衡的部署持续正常工作：这样一个实例用新密钥签名的令牌就能被其他每个实例接受。

开始使用新密钥签名

在签发令牌的实例（all 和 web）上，改用新密钥并以其 ID 签名，然后重启这些实例：

CONSOLE_RBAC_SIGNING_KEY_FILE=/etc/openvox-console/rbac-verification-keys/2026-10-01.pem CONSOLE_RBAC_SIGNING_KEY_ID=2026-10-01

新的登录现在会获得用新密钥签名的令牌。用旧密钥签名的令牌仍然有效，因为每个实例仍然接受旧密钥。

停用旧密钥

令牌最长存活 24 小时：这就是刷新令牌的有效期。在最后一个实例开始使用新密钥签名满 24 小时后，从每个实例的验证目录中删除旧密钥文件，然后重启这些实例。从那时起，用旧密钥签名的令牌都会被拒绝。

过早删除旧密钥，会让所有持有由它签名的令牌的人退出登录。删除旧密钥后又丢失新密钥，则会让所有人退出登录。在停用旧密钥之前，请先备份新密钥。
