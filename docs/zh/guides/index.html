循序渐进：安装控制台、添加 Nodes、横向扩展，以及日常运维。每条命令都与你实际输入的完全一致。

安装

你要构建的是什么、开始之前需要确定的名称，以及应当遵循哪份安装指南。

使用 Docker Compose 运行 openvoxserver、openvoxdb、两个数据库和控制台，从一台空主机到一个可以接入 Nodes 的控制台。

从软件包安装 openvoxserver、openvoxdb 和 Postgres，构建控制台，并将其作为 systemd 服务运行。

Nodes

在 Linux、macOS 或 Windows 上用一个脚本注册 Node，为其证书签名，并看到它连接和运行。

从控制台对 Node 证书进行签名、吊销和清理，以及每种操作对已连接 Node 的影响。

从控制台删除 Node、此操作在 openvoxdb 和 CA 中的作用，以及会保留哪些内容。

控制台如何自动升级你的 Nodes 上的 Node 代理、如何查看哪些 Nodes 落后，以及对于在此功能出现之前安装的 Nodes 需要执行的一次性步骤。

扩展

控制台的每种运行模式提供和运行什么，以及每种模式需要配置什么。

将第二个控制台实例加入集群，把实例拆分为不同的运行模式，并把分类服务部署在编译器旁边。

使用

借助一棵按 Facts 匹配或按名称固定的 Node 组树，决定每个 Node 获得哪些类、参数和 Environment。

从一个或多个 control 仓库把 Puppet 代码 deploy 到 openvoxserver 用于编译的 Environments 中。

在单个 Node、一组选中的 Nodes、查询匹配的 Nodes 或某个 Node 组上按需运行 Puppet 或 Puppet Task，并查看每个 Node 做了什么。

构建一个 Plan（按顺序执行的一系列 Puppet 运行和 Tasks），保存它，在你选择的 Nodes 上运行它，并观察每个步骤。

保存一次 Puppet 运行、一个 Task 或一个 Plan，以便稍后启动——一次或重复启动——其 Nodes 会在每次启动时重新确定。

通过角色和权限授予人员访问权限，使用你的身份提供方登录，并为程序签发令牌。

设置漏洞提供方，解读机群的发现，并了解每个提供方能看到什么、看不到什么。

扫描 Linux Nodes 上待安装的软件包更新，然后分批为它们打补丁，支持试运行、停止阈值和可选的重启。

注册控制台通过 SSH 访问的主机，固定其主机密钥，检查它们，并像在任何其他 Node 上一样在其上运行 Tasks。

运行存放在你的模块中的 YAML Plans，支持带类型的参数、在步骤之间传递结果，并且每个 Task 都会依据你的 Node 组进行检查。

为 AI 代理提供专属的受限令牌，让它读取机群并请求更改，并在任何东西运行之前由你亲自批准每项更改。

运维

通过提升流复制备库，从控制台数据库丢失中恢复。

在不让任何人退出登录的情况下，替换控制台用于签名登录令牌的密钥。

通过导出和恢复，把容器部署中的两个数据库从 Postgres 17 迁移到 18。

OpenVox Console 以容器镜像形式发布，每次 push 都会构建 amd64 和 arm64 版本，同时也提供单个二进制文件。安装指南将带你从一台空主机走到一套可用的部署——openvoxserver、openvoxdb、Postgres 和控制台——可以用容器，也可以用软件包。
