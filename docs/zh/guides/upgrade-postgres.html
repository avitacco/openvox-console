运维

将容器数据库升级到 Postgres 18

通过导出和恢复，把容器部署中的两个数据库从 Postgres 17 迁移到 18。

生产 compose 文件让两个数据库都运行在 Postgres 18 上。Postgres 18 镜像把数据保存在卷内一个以版本号命名的目录中，因此卷挂载在 /var/lib/postgresql，而不是以前的 /var/lib/postgresql/data。

针对一个仍保存着 Postgres 17 数据的卷启动 Postgres 18 容器时，它会拒绝启动，错误信息以 Error: in 18+, these Docker images are configured to store database data in a format which is compatible with "pg_ctlcluster" 开头。这只是拒绝启动，并非损坏：旧数据完好无损。本指南会把数据迁移过去。

升级方式是导出再恢复：pg_upgrade 需要在同一个镜像中同时具备两个版本，而这些镜像只带一个版本。

导出两个数据库

请在 Postgres 17 容器仍在运行时执行此操作。停止向它们写入的服务，但保持数据库运行：

docker compose -f docker-compose.yml stop console openvoxdb docker compose -f docker-compose.yml exec -T openvoxdb-postgres \ pg_dumpall -U openvoxdb > openvoxdb-17.sql docker compose -f docker-compose.yml exec -T console-postgres \ pg_dumpall -U console > console-17.sql

继续之前，检查两个文件都已存在且不为空：

ls -l openvoxdb-17.sql console-17.sql

替换卷

这会删除 Postgres 17 的数据。从这里开始，两个导出文件就是唯一的副本，这也是为什么要先做上面的检查。

 docker compose -f docker-compose.yml down docker volume rm openvox-console_openvoxdb-postgres-data openvox-console_console-postgres-data

卷名称取决于项目目录的名称；请用 docker volume ls 确认。

在 Postgres 18 上恢复

只启动数据库。它们启动时是空的，openvoxdb 的数据库会从 compose 文件获得它所需的 pg_trgm 扩展：

docker compose -f docker-compose.yml up -d openvoxdb-postgres console-postgres docker compose -f docker-compose.yml exec -T openvoxdb-postgres \ psql -U openvoxdb < openvoxdb-17.sql docker compose -f docker-compose.yml exec -T console-postgres \ psql -U console < console-17.sql

然后启动其余所有服务：

docker compose -f docker-compose.yml up -d

如果 openvoxdb 提示缺少 pg_trgm

没有 pg_trgm 扩展时 openvoxdb 会拒绝启动。compose 文件只在首次创建数据库时添加该扩展，因此对于已经存在的数据库，需要手动添加：

docker compose -f docker-compose.yml exec openvoxdb-postgres \ psql -U openvoxdb -c 'CREATE EXTENSION IF NOT EXISTS pg_trgm;'

继续使用 Postgres 17

继续使用 17 需要两处更改，而不是一处：设置 OPENVOXDB_POSTGRES_VERSION=17-alpine（以及控制台对应的 CONSOLE_POSTGRES_VERSION），并且把每个卷的挂载点改回 /var/lib/postgresql/data。只修改版本会导致上述错误。
