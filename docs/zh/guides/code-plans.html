使用

运行代码中的 Plans

运行存放在你的模块中的 YAML Plans，支持带类型的参数、在步骤之间传递结果，并且每个 Task 都会依据你的 Node 组进行检查。

代码 Plan 是位于模块 plans 目录中的 YAML 文件，格式与 Bolt 和 Puppet Enterprise 所用的相同。控制台从它 deploy 的代码中读取该文件并自行运行：一步接一步，并在步骤之间传递结果。它不需要 Bolt，也不需要 Puppet 语言。

这与已保存的 Plan 不同，后者是你在控制台中构建的固定的一系列 Puppet 运行和 Tasks，在一组 Nodes 上运行。代码 Plan 与你的代码放在一起，接受自己的参数，并根据之前的步骤决定每个步骤的目标。

读取 Plans 列表需要 orchestrator:read。运行 Plan 需要 orchestrator:run。不涉及任何新权限。

Plans 从哪里来

控制台会按照 environment.conf 中 modulepath 的顺序（如果没有则为 modules），在每个 Environment 的模块中查找 <module>/plans/<name>.yaml。Plan 命名为 module::name；对于 init.yaml，则直接命名为 module。如果同一名称出现在两个目录中，与 Puppet 一样，先找到的胜出。

这些文件读取自 deploy 你代码的那个控制台实例的代码目录（CONSOLE_CODE_DIR_PATH）。不持有已 deploy 代码的实例无法列出或运行 Plans，并会如实说明，而不是显示一个空列表。请从负责 deploy 的实例运行 Plans。

打开 Jobs，然后打开 Plans：代码中的计划部分会列出某个 Environment 的 Plans。控制台无法运行的 Plan 会被列出并注明原因，指出相应的步骤。

Plan 能做什么

Plan 包含 description、parameters、steps 和 return：

description: Restart a service, then check it parameters: targets: type: TargetSpec description: Where to restart it service: type: String[1] default: nginx token: type: Optional[Sensitive[String]] steps: - name: restart description: Restart the service task: service::restart targets: $targets parameters: name: $service - name: status task: service::status targets: $restart.ok_targets parameters: name: $service - message: "checked ${status.targets}" return: restarted: $restart.ok_targets healthy: $status.ok

参数需要声明 type、可选的 default 和 description。类型与 Tasks 使用的相同（String、Integer[1, 10]、Boolean、Array[String]、Enum['a','b']、Optional[...] 等），另外还有 TargetSpec（Nodes）和 Sensitive[...]。没有默认值且不是 Optional 的参数为必填。如果参数缺失、未知或类型错误，控制台会在任何东西启动之前拒绝运行，并指出该参数。

每个步骤只能执行以下其中一项：

  • task: module::task，带 targets 和 parameters。运行该 Task。
  • plan: module::plan，带 parameters。作为本 Plan 的一部分运行另一个 Plan。Plan 最多可以嵌套调用五层，并且永远不能调用自身。
  • message: text。把文本打印到该次运行的记录中。

步骤可以有一个 name，使其结果以 $name 的形式供后续步骤使用，也可以有一个 description。

引用的形式为 $name、$name.field、$name[0] 和 $name['field']，可引用参数或之前的步骤。仅由一个引用构成的字符串会保留该值的类型（列表仍是列表）。在文本中，请写作 ${name.field}；美元符号写作 $$。语法就这么多：没有运算符，没有条件判断，也没有函数。在写在一行内的 YAML 列表或映射中，包含 [ 或 , 的引用需要加引号。

步骤的结果包含：

字段 内容
ok 所有目标均成功
results 每个目标的 target、ok、value 和 error
targets, ok_targets, error_targets Node 名称
value Task 的结果（针对单个 Node 上的步骤）

Task 的 value 是它以 JSON 形式打印的内容，或者以 _output 形式提供的文本。

如果某个 Task 步骤在任何目标上失败，Plan 就在那里失败：之后的步骤会被记录为未运行，不会再发送任何东西。目标为空的步骤（比如，之前某个步骤一个成功的都没有）不会运行任何东西，并被视为成功。

不支持：command、script、upload、download、resources 和 eval 步骤、Puppet 语言表达式、并行运行步骤、重试和捕获错误，以及计划运行代码 Plan。使用了其中任何一项的 Plan 会被列为不可用，并注明原因。Bolt 的 Puppet 语言 Plans（.pp）不会被运行。

运行一个 Plan

在某个 Plan 旁选择运行。表单根据其参数生成；将字段留空即使用默认值。Nodes（TargetSpec）以名称列表、查询或 Node 组的形式给出，在 Plan 启动时解析一次，并会先进行预览。该运行会以 Job 的形式打开；其页面会实时显示每个步骤：其状态、它启动的 Job、消息打印的内容，以及步骤失败的原因，还有 Plan 返回的值和传入的参数。

范围与权限

Plan 不能做任何你无法手动完成的事。当你启动它时：

  • 每个步骤指定的 Task 都必须存在，并且是你的角色所允许的，否则请求会被拒绝，并指出该步骤；
  • 你指定的 Nodes 必须位于你的 Node 组中，否则整个请求都会被拒绝；
  • 每执行到一个步骤，都会依据你的 Node 组检查其目标，并依据你的允许列表检查其 Task，与你自己启动的 Task 完全相同。会被拒绝的步骤会使 Plan 在那里失败，并给出原因。

无代理目标可以在 Task 步骤中使用。

仅限部分 Node 组的读者，只有当某次 Plan 运行在其 Nodes 上运行过时才能看到它；如果它同时也在其他 Nodes 上运行过，则看不到它打印的内容、返回值或传入的值。

敏感值

类型为 Sensitive[...] 的参数永远不会被记录下来：在存储的参数、跟踪记录、消息、返回值、日志和审计条目中都显示为 [redacted]，并且只会到达被传入的那个 Task 参数。敏感值只能传递给本身也是 Sensitive 的参数。

长时间运行

Plan 可以运行数小时，最长 24 小时。控制台会在运行过程中不断告知 Job 它仍然存活。如果跟踪它的控制台实例停止，该 Plan 会在最后一次收到消息的十分钟后被判为失败；已经启动的步骤会在其 Nodes 上继续执行。一次运行最多 200 个步骤，一个步骤最多 1000 个目标；超出限制会使 Plan 失败，并指出是哪项限制。

Plan 的启动和结束都会生成审计条目，记录操作者、哪个 Plan 和 Environment，以及所传参数的名称，但绝不记录其值。
