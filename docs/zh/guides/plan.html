安装

规划部署

你要构建的是什么、开始之前需要确定的名称，以及应当遵循哪份安装指南。

你要构建的是什么

一套可用的 OpenVox Console 部署由五个部分组成：

组件 它能做什么 默认端口
openvoxserver 编译 catalog，并且是证书颁发机构，其他所有组件的身份都来自它 8140
openvoxdb 存储 Facts、Reports 和软件包清单；控制台向它查询 8081
openvoxdb 的 Postgres openvoxdb 自身的存储 5432
控制台的 Postgres 控制台自身的存储：用户、角色、组、Jobs 和审计 5432
控制台 Web 界面和 API，以及受管 Nodes 所连接的 Node 传输 8080, 8142

两个 Postgres 数据库是相互独立的。它们可以共用一台服务器，但控制台和 openvoxdb 绝不共用同一个数据库。

导致大多数部署失败的两件事

  1. 所有组件都通过同一个 CA 签发的证书进行认证，即 openvoxserver 内部的 CA。控制台持有它签发的几个独立身份：一个用于 openvoxdb 的客户端证书、一个用于 Node 传输的服务器证书，以及一个可选的证书管理员凭据。因此 openvoxserver 总是最先部署。
  2. 名称比地址更重要。证书只对签发时写入的名称有效。请事先决定每个组件将以哪个名称被访问——从每一个访问它的方向——并把这些名称写入它的证书。之后再添加名称就意味着要重新签发证书。

开始之前先决定这些

决策项 用途 示例
openvoxserver 的名称（Nodes 访问它所用） 接入 Nodes puppet.example.com
openvoxserver 的名称（控制台访问它所用） 从控制台管理证书 相同，或者一个内部名称
控制台的基础 URL 安装脚本的下载地址和链接 https://console.example.com
Node 传输地址（Nodes 拨号所用） Nodes 与控制台之间保持的长连接 console.example.com:8142

如果控制台访问 openvoxserver 时使用的名称与 Nodes 使用的不同，那么两个名称都必须写入 openvoxserver 的证书。

如果在与 openvoxdb 相同的主机上运行控制台，端口 8080 会发生冲突，因为 openvoxdb 也监听 8080。此时控制台会启动失败并报 "address already in use"。在共用主机上，请用 CONSOLE_HTTP_ADDR=:8088 把控制台移到其他端口，并相应修改 CONSOLE_BASE_URL。

选择安装指南

两份指南的终点相同：控制台向 openvoxserver 提供分类，准备好接入 Nodes。

  • 使用容器安装：用项目发布的镜像，通过 Docker Compose 运行所有组件。这是最快的途径，除非你有理由不这样做，否则就选它。
  • 从软件包和二进制文件安装：从 OpenVox 和发行版的软件包安装 openvoxserver、openvoxdb 和 Postgres，并以 systemd 服务的形式运行控制台。

各组件可以自由互通，因此你也可以混合使用两种方式，例如用软件包安装的 openvoxserver 搭配容器化的控制台。

你要构建的是什么 导致大多数部署失败的两件事 开始之前先决定这些 选择安装指南

OpenVox Console 以容器镜像形式发布，每次 push 都会构建 amd64 和 arm64 版本，同时也提供单个二进制文件。安装指南将带你从一台空主机走到一套可用的部署——openvoxserver、openvoxdb、Postgres 和控制台——可以用容器，也可以用软件包。
