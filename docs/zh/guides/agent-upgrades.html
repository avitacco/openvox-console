Nodes

保持 Node 代理为最新

控制台如何自动升级你的 Nodes 上的 Node 代理、如何查看哪些 Nodes 落后，以及对于在此功能出现之前安装的 Nodes 需要执行的一次性步骤。

Node 代理是安装脚本放在每个 Node 上的小型服务。它维持该 Node 与控制台的连接，并执行你启动的运行和 Tasks。它与控制台一同构建并内置于控制台中，因此更新的控制台通常会带来更新的 Node 代理。

控制台会替你升级 Nodes 上的 Node 代理。当 Node 连接时，控制台会询问它运行的是哪个代理构建版本。如果该版本比控制台附带的版本旧，控制台就会通知该 Node 升级，Node 会从控制台下载新版本，进行校验、安装，并重启为新版本。你无需在 Node 上做任何事。

你会看到什么

  • Nodes 页面。代理落后的 Node 会被标记为客户端已过期。
  • Node 页面。显示代理的版本及其构建时间、是否为最新，以及上一次升级尝试的结果。
  • Dashboard。在集群状态下，显示有多少 Node 代理是最新的、有多少已过期、有多少次升级失败，以及自动升级是否开启。

从 Node 页面自行启动升级，需要在 Node 组包含该 Node 的角色上拥有 nodes:manage。控制台自行启动的升级不受任何人的 Node 组限制。

自控制台升级以来尚未连接过的 Node 会显示为尚未上报，而不是已过期。它会在下次连接时上报。

在自动升级功能出现之前安装的 Nodes

在此功能出现之前的 Node 代理无法自行升级，因为它不理解该请求。控制台会把这样的 Node 显示为已过期，并注明需要重新运行安装脚本。在该 Node 上运行一次，方式与添加 Node 时完全相同：

Linuxcurl -fsSL https://console.example.com/packages/install.sh | sudo bash macOScurl -fsSL https://console.example.com/packages/install-macos.sh | sudo bash WindowsInvoke-WebRequest https://console.example.com/packages/install.ps1 -OutFile install.ps1 .\install.ps1

从此以后，该 Node 会自行保持最新。Dashboard 会统计仍在等待这一步的 Nodes 数量，因此你可以知道何时已全部完成。

如果你改用 Puppet 管理 Linux 软件包，那么对控制台仓库中的 node-agent-client 软件包设置 ensure => latest 也能达到同样的效果。

升级会做什么、不会做什么

  • 它从不打断工作。正在执行运行或 Task 的 Node 会被跳过，一分钟后再试。
  • 安装前会先校验。控制台通过 Node 的已认证连接发送下载文件的预期校验和。Node 会拒绝任何不匹配的文件，并在替换旧代理之前先启动一次新代理以确认其能正常工作。任一检查失败，Node 都会保留现有的代理。
  • 每次只处理少量 Nodes。无论有多少 Nodes 落后，最多同时升级 20 个。
  • 它只会向前升级。运行着比控制台所提供版本更新的代理的 Node 会被跳过。在升级控制台实例集群的中途，或在回滚控制台之后，你会看到这种情况。
  • 在 Linux 上通过包管理器进行。Node 会安装控制台的 .deb 或 .rpm，因此 dpkg 和 rpm 显示的是真正安装的版本。

macOS 和 Windows 上的升级已被项目测试覆盖，但还没有在真实的 macOS 和 Windows 主机上完整地端到端运行过。如有任何与此处描述不符的情况，请反馈。

当升级失败时

Node 页面会用该 Node 自己的话显示原因：下载失败、校验和不匹配、包管理器正忙。控制台会在五分钟后重试，之后每次等待的时间加倍，在同一构建版本上失败五次后停止。

最常见的原因是 Node 无法访问控制台的基础 URL（CONSOLE_BASE_URL），而它正是从那里下载新代理的。安装脚本使用的也是同一个地址，因此请检查自该 Node 安装以来发生了什么变化。

修复原因之后，在该 Node 的页面上选择升级客户端即可立即重试。这需要 nodes:manage 权限，且该 Node 必须已连接。无论自动升级是否开启都有效，在自动尝试停止之后也同样有效。

当你把控制台升级到附带不同 Node 代理的版本时，控制台也会自行重新开始升级。

关闭自动升级

要阻止控制台自动升级 Node 代理，请在每个控制台实例上设置此项并重启：

CONSOLE_AGENT_AUTO_UPGRADE=false

控制台仍会记录每个 Node 的代理构建版本，仍会显示哪些 Nodes 已过期。Node 页面上的升级客户端仍然有效。

如果只想让单个 Node 例外，请在该 Node 上为 Node 代理设置 NODE_AGENT_ACCEPT_UPGRADES=false 并重启它：

平台 在哪里设置
Linux 把这一行添加到 /etc/node-agent-client/local.env，然后执行 sudo systemctl restart node-agent-client
Windows 将其设置为系统环境变量，然后重启 node-agent-client 服务
macOS 将其添加到 /Library/LaunchDaemons/org.voxpupuli.node-agent-client.plist 中的 EnvironmentVariables，然后重新加载该任务

随后 Node 页面会显示该 Node 拒绝升级，控制台也不会再尝试。在 macOS 上，再次运行安装脚本会重写该文件，因此之后请重新设置。
