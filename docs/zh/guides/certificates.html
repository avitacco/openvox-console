Nodes

管理 Node 证书

从控制台对 Node 证书进行签名、吊销和清理，以及每种操作对已连接 Node 的影响。

每个 Node 的身份都是 openvoxserver 的 CA 签发的一张证书。配置了证书管理员凭据后，控制台的 Nodes 页面会显示每张证书的状态，并允许你对其进行操作。

开启证书管理

证书管理需要在安装期间签发的证书管理员凭据。两份安装指南都介绍了如何签发它。当以下四项设置全部存在时，控制台就会使用它：

设置 说明
CONSOLE_CA_CLIENT_URL openvoxserver 的地址（控制台访问它所用）
CONSOLE_CA_CLIENT_CERT_FILE 该凭据的证书
CONSOLE_CA_CLIENT_KEY_FILE 其私钥
CONSOLE_CA_CLIENT_CA_FILE CA 证书包，用于验证 openvoxserver

只要其中任何一项未设置，每个 Node 的证书状态都会显示为 unknown，控制台的其余部分照常工作。

该凭据拥有完整的 CA 管理员权限：任何能够使用它的东西都可以签名、吊销和清理任何 Node 的证书。openvoxserver 没有权限更窄的变体。请确保其密钥只有控制台可以读取。

决定谁可以操作证书

涉及两项权限，而且它们被有意设计得相距甚远：

权限 允许
nodes:read 查看每个 Node 及其证书状态
nodes:certs:manage 对证书进行签名、吊销和清理

授予 nodes:certs:manage 等同于授予 CA 的 shell 访问权限：无法做到只允许签名而不允许吊销，也无法只允许某个 Node 而不允许另一个。请只把它授予特定的可信操作员，而不是每个需要查看 Node 状态的人。

让团队为自己的 Nodes 签名

在特定 Node 组上被授予的角色，只能对这些组中的 Nodes 的证书进行操作——参见用户、角色与令牌。等待签名的新 Node 从未运行过 Puppet，因此没有 Facts，也不在任何组的规则中。要让某个团队为它签名，请先把它的名称固定到该团队的组：

  1. 打开组以及该团队的组。该组必须直接位于 All Nodes 之下；在更深层的组中，只有当该 Node 也被固定到其上层的每个组时，固定才有效。
  2. 在固定的 Nodes 下，按该 Node 注册时将使用的名称原样添加，然后保存。这需要 classifier:write。
  3. 该团队中持有 nodes:certs:manage 的人现在可以在 Nodes 页面上看到该请求，并为其签名。

一旦该 Node 运行过 Puppet，其 Facts 就会照常把它归入各组，届时即可移除该固定。与以前一样，角色在 All Nodes 上被授予的任何人都可以为任何请求签名。

签名、吊销或清理

在 Nodes 页面上，每个 Node 的证书状态是 requested、signed、revoked 或 unknown 之一，可用的操作取决于该状态：

操作 可用条件 它能做什么
签名 requested 签发该 Node 的证书，使其能够进行认证
吊销 signed 使该证书在任何地方都永久不再被接受
清理 任何已知状态 必要时先吊销证书，然后彻底删除 CA 中该 certname 的记录

在 Node 以相同名称重新注册之前，应使用「清理」：记录一旦删除，该 certname 就可以提交新的请求。

CA 拒绝的操作，例如为一个并未等待签名的证书签名，会失败并给出原因，且不做任何更改。每个完成的操作都会以 node.certificate.signed、node.certificate.revoked 或 node.certificate.cleaned 写入审计日志。

吊销对已连接 Node 的影响

通过控制台吊销或清理的 Node 会被立即切断。每个控制台实例都会收到通知，持有该 Node 连接的实例会关闭连接。每个实例还会先获取 CA 当前的吊销列表，因此该 Node 无法简单地重新连接。

在控制台之外（在 CA 主机上用 puppetserver ca revoke）吊销的证书同样会被发现：每个实例每分钟重新读取一次吊销列表，并断开任何现已被吊销的活动连接。

吊销列表来自以下两处之一：

  • 由 CONSOLE_NODE_TRANSPORT_CRL_FILE 指定的文件，通常是控制台主机自身 Puppet 代理的 crl.pem，代理会使其保持最新。如果设置了该项但文件无法读取，控制台会拒绝启动；
  • 否则，由 CA 本身通过证书管理员凭据提供。

如果两者都没有，控制台会在启动时记录一条警告：此时被吊销的 Node 证书仍然可以连接。

基础设施证书

Nodes 页面列出 CA 已知的每个 certname，其中包括控制台自己的证书以及与它通信的服务器的证书：在默认安装中是 console、node-transport、console-ca-client、openvoxdb 和 openvoxserver。这些证书会被自动识别并默认隐藏。显示基础设施证书会把它们带标记地显示出来，吊销或清理其中任何一张时，都会要求你确认，并指出会导致什么出问题。

停用证书管理员凭据

由于它拥有完整的 CA 管理员权限，一旦不再需要，请立即清理该凭据，例如在某个控制台实例退役时。在 CA 主机上执行：

sudo /opt/puppetlabs/bin/puppetserver ca clean --certname console-ca-client

然后从每个仍在使用该凭据的控制台中删除四项 CONSOLE_CA_CLIENT_* 设置。仍持有已清理凭据的控制台只会把每张证书都报告为 unknown；其他功能都不会停止工作。
