运维

故障切换到备用数据库

通过提升流复制备库，从控制台数据库丢失中恢复。

控制台把所有持久数据都保存在其 Postgres 数据库中，控制台本身没有任何需要恢复的东西。因此，主数据库丢失后的恢复方法就是提升一个备库，并让控制台指向它。本操作手册假定备库通过 Postgres 自身的流复制保持同步。

在需要之前先检查备库

在备库上：

psql -U console -d console -c "SELECT pg_is_in_recovery();"

它返回 t：它仍然是副本。对它的写入会被拒绝并报 cannot execute INSERT in a read-only transaction，健康的副本也是如此。

提升备库

psql -U console -d console -c "SELECT pg_promote();"

几秒钟内 pg_is_in_recovery() 就会返回 f：备库现在是一个独立的、可写的数据库。

即使旧主库恢复，被提升的数据库也不会继续从旧主库复制。从此刻起，请把旧主库视为已退役。如需重新拥有备库，请用 pg_basebackup -R 把旧主库重建为被提升数据库的新备库。

让控制台指向它

把 CONSOLE_POSTGRES_DSN 改为被提升的数据库的地址，然后重启控制台。控制台只在启动时建立一次连接，因此必须重启。如果有多个实例，请逐一重启。

在数据库前放置一个连接池或代理，可以为控制台提供一个在故障切换后依然有效的地址。这样只需重新指向代理，控制台自身的配置永远不必改动。

确认控制台已恢复

/health 再次报告 Postgres 为 ok。然后登录：登录会写入数据库，因此它证明的是写入正常，而不仅仅是读取正常。
