运行模式

控制台的每种运行模式提供和运行什么，以及每种模式需要配置什么。

同一个镜像，同一个二进制文件。CONSOLE_RUN_MODE 决定一个实例运行控制台的哪些部分，这样负载差异很大的部分就可以分别扩展和部署。不设置时为 all：所有部分都在同一个实例中，单实例部署始终如此运行。

每种模式运行什么

模式 提供内容 监听 后台运行内容
all（默认） 所有内容 HTTP、Node 传输 所有后台任务
web 控制台、其 API、代码 deploy webhook 以及分类 HTTP 跟踪通过它启动的 Jobs
enc 仅分类 HTTP 无
orchestrator 仅健康检查和指标 HTTP、Node 传输 Job 派发、计划的 Jobs、新 Nodes 的首次运行，以及 Node 代理升级
worker 仅健康检查和指标 HTTP 漏洞同步，以及清理被遗弃的 Jobs

每种模式都提供 /health 和 /metrics，因此无需知道实例的模式就可以检查它，而且 /health 会报告它正在运行的模式。

该表中有两个选择是有意为之：

  • web 同样提供分类应答。enc 的存在是为了让分类可以单独运行在编译器旁边，而不是让其他地方都缺失分类。一个悄无声息地停止为 Nodes 分类的拆分方案，远比让 web 分担部分负载糟糕得多。
  • orchestrator 不提供 API。它持有 Node 连接，并通过这些连接下发 Jobs。启动 Job 是 web 的工作，web 通过集群访问这些连接。
  • Job 由启动它的实例跟踪。在控制台中启动的运行、Task 或 Plan 由接收该请求的 web 实例发送和跟踪，因此 web 实例必须与 orchestrator 实例组成集群，才能访问任何 Node。如果该 web 实例在 Job 结束前停止，该 Job 会被某个 worker 实例标记为失败。

每种模式需要什么

每种模式只要求它用到的设置，缺少时会拒绝启动，并指出缺少的设置：

模式 所需设置
所有模式 CONSOLE_POSTGRES_DSN 以及四个 CONSOLE_OPENVOXDB_* 设置
all, web CONSOLE_RBAC_SIGNING_KEY_FILE：只有这些模式会签发登录令牌
enc, orchestrator, worker CONSOLE_RBAC_VERIFICATION_KEYS_DIR：它们校验令牌，但从不签发令牌
orchestrator CONSOLE_NODE_TRANSPORT_ADDR：如果没有 Node 监听器，在一个看起来健康的实例上，每个 Job 都会以 "not connected" 失败

为调度器提供计划的 Jobs 所需的设置

计划的 Jobs 由 all 和 orchestrator 实例启动，而不是由 web 启动。orchestrator 实例没有以下设置也能启动，但需要其中某项设置的计划会被跳过（并说明原因），直到该实例具备该设置为止：

  • CONSOLE_PUPPET_SERVER_URL，用于启动计划的 Task：计划启动时，会在已 deploy 的代码中查找该 Task。
  • CONSOLE_SECRETS_KEY_FILE（与 web 上的密钥相同），用于启动带有敏感参数的计划 Task。

当多个实例运行调度器时，每个到期时间都只由其中一个实例启动。如果计划到期时没有实例在运行，它会在有实例运行时启动——除非已经晚了超过 15 分钟，那样的话该次时间会被记录为已错过。

为不签发令牌的模式提供验证密钥

只校验令牌的实例会从一个目录中读取用于校验的密钥，每个密钥一个文件，以密钥 ID 命名。从未轮换过密钥的部署使用 ID default，因此该目录中只有一个文件 default.pem，也就是签名密钥文件本身：

sudo install -d -m 0750 -o root -g openvox-console /etc/openvox-console/rbac-verification-keys sudo install -m 0640 -o root -g openvox-console \ rbac-signing-key.pem /etc/openvox-console/rbac-verification-keys/default.pem CONSOLE_RUN_MODE=enc CONSOLE_RBAC_VERIFICATION_KEYS_DIR=/etc/openvox-console/rbac-verification-keys

验证目录目前只接受与签名密钥格式相同的密钥：即私钥，控制台只使用其中的公钥部分。因此，被提供该目录的实例也持有一个可以签名令牌的密钥。请在每台主机上像保护签名密钥一样保护它，包括编译器旁边的 enc 实例。

轮换签名密钥时，每个实例的验证目录也需要加入新密钥；具体顺序参见轮换令牌签名密钥。

更改实例的模式

设置 CONSOLE_RUN_MODE 并重启该实例。不会迁移任何数据：每种模式都读写同一个数据库。把它改回 all 即可撤销更改。

单个实例也可以更改模式，但只有在多个集群实例共同运行所有模式时，all 以外的模式才有意义。参见运行更多实例。
