使用内置的 g10k 从 control 仓库 deploy Environments。可按需触发，也可直接由 push 触发，并记录每一次 deploy。

一个 control 仓库，或每个团队一个

维护自有 control 仓库的团队不必再共用一个。把每个仓库添加为来源，并为需要的仓库指定前缀，这样两个都有 production 分支的仓库会落在各自独立的 Environments 中，而不会相互覆盖。

sources: control: remote: https://git.example.com/infra/control-repo.git prefix: false team_a: remote: https://git.example.com/team-a/control.git prefix: true

每次 deploy 都留下痕迹

谁触发的、来自哪个来源和哪个 ref、写入了哪个 Environment，以及是否成功。失败的 deploy 会保留其错误，而不会从列表中悄然消失。

每个仓库都有自己的 webhook 和自己的密钥，因此从一个仓库泄露的密钥无法用来 deploy 另一个仓库。

OpenVox Console 以两个容器镜像的形式发布，每次 push 都会为 amd64 和 arm64 构建。SETUP.md 会带你完成一次真实部署——openvoxserver、openvoxdb、Postgres 和控制台——同时给出容器和软件包两种说明。
