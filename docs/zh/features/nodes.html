从需要关注的地方开始

运行结果按你分诊的方式分组：哪些失败了、哪些是有意变更、哪些纠正了漂移，以及哪些本来就符合要求。可达性单独跟踪，因为一个陷入沉默的 Node 和一个上报了失败的 Node 是两个不同的问题，解法也不同。

用任意 Fact 搜索机群

按名称筛选，或按代理上报的任何内容筛选——操作系统、内核、架构，或你自定义的 Fact。答案来自此刻的 openvoxdb，而不是缓存。

证书状态就在旁边；配置了 CA 访问后，你可以在同一页面完成签发和吊销，而不必去服务器上找一个 shell。

完整呈现一个 Node

Node 自己的页面汇集了它的 Facts、最近的运行、分类赋予它的类、已安装的内容，以及影响它的漏洞——当问题是一台机器而不是整个机群时，你需要的一切都在这里。

一次运行产生的每个资源事件都在这里，附带每项变更的新旧值，以及导致它的 manifest 和行号。这是代理发送的原始内容，而不是它的摘要。
