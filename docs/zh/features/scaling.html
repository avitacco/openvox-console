控制台是一个 Go 二进制文件，也是一个容器镜像。同一个二进制文件既可以运行单个一体化实例，也可以运行一组各司其职的实例。

从一个实例开始

控制台、访问控制、分类、编排和代码 deploy 默认在同一个进程中运行。没有需要拼接的东西，没有需要保持同步的内部服务，只有一样东西需要升级。

机群增长时按职责拆分

一项设置决定实例运行什么，因此每个部分都可以单独扩展和部署。所有持久数据都存放在 Postgres 中，因此每种实例都可以同时运行任意多个。

控制台及其 API，位于你的负载均衡器之后。 持有与你的 Nodes 之间的连接，并运行通过这些连接下发的 Jobs。 后台工作，例如漏洞同步，无论运行多少个实例都只执行一次。 仅提供分类，运行在你的编译器旁边。

集群化，并且默认安全

实例通过双向 TLS 加入同一个集群，使用的是你的 OpenVox CA 已经签发的证书。被吊销的登录或 Node 证书会同时被每个实例拒绝，在任何实例上启动的 Job 都能到达连接在任何其他实例上的 Node。

分类实例由外向内接入：连接从编译器旁边发起，连到核心，因此核心永远不需要进入那个网络的通道，而且这些实例从不承载 Node 流量。

一个页面看遍所有实例

系统页面会请每个实例描述自身情况：其运行模式、健康状况、运行时间和后台工作，以及它眼中控制台所依赖的每项服务的状态。本应应答却没有应答的实例会被明确指出，而不是被悄悄略去。

先添加第二个一体化实例，再根据负载需要拆分角色。每一步都可以撤销，只需把实例改回运行全部功能即可。

动手操作

控制台的每种运行模式提供和运行什么，以及每种模式需要配置什么。

将第二个控制台实例加入集群，把实例拆分为不同的运行模式，并把分类服务部署在编译器旁边。

OpenVox Console 以容器镜像形式发布，每次 push 都会构建 amd64 和 arm64 版本，同时也提供单个二进制文件。安装指南将带你从一台空主机走到一套可用的部署——openvoxserver、openvoxdb、Postgres 和控制台——可以用容器，也可以用软件包。
