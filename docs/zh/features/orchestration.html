在你挑选的 Nodes 上运行 Puppet、Tasks 和 Plans——立即运行或按计划运行——并看着结果一个 Node 接一个 Node 地返回。

按 Node 而非按 Job 给出结果

每个目标都被单独记录：状态、退出码和输出。一个在九个 Nodes 上成功、在一个上失败的 Job 会如实呈现，而不会收敛成一个你之后还得去追查的单一结论。

当某个 Job 触发了 Puppet 运行时，其结果会直接链接到该次运行产生的 Report——于是「这究竟改变了什么」只需一次点击。

Tasks、Plans 与计划

运行你已 deploy 的代码中的 Task，其参数会依据其声明的类型进行检查，敏感值不会出现在任何记录中。把 Puppet 运行和 Tasks 串联成一个可以保存并再次运行的 Plan。或者在你的代码旁用 YAML 编写 Plan，支持带类型的参数以及在步骤之间传递结果，由控制台来运行——无需 Bolt。

把其中任何一种保存下来，以便稍后启动，一次或重复启动。计划在每次触发时选择其 Nodes，并以其所有者在那一刻拥有的访问权限运行，因此所有者不再有权做的事，计划也会停止去做。

按规则而非按列表选择目标

指定 Nodes、指向某个 Node 组或编写 PQL 查询，控制台会在 Job 启动时确定具体的 Nodes。可以按次以 No-op 方式运行 Puppet 以查看它将会更改什么，也可以针对另一个 Environment 运行，或带调试输出运行。

无法运行代理的主机仍然可以通过 SSH 访问。在它们上面运行 Tasks 与在任何 Node 上一样。

Targets recorded, each one pending. Work goes out to the nodes. Each node reports back as it finishes. The job takes the status its targets add up to.

编排基于 NATS 运行，因此覆盖大型机群只是增加容量的问题，而不必重做消息路由方式。

动手操作

在单个 Node、一组选中的 Nodes、查询匹配的 Nodes 或某个 Node 组上按需运行 Puppet 或 Puppet Task，并查看每个 Node 做了什么。

构建一个 Plan（按顺序执行的一系列 Puppet 运行和 Tasks），保存它，在你选择的 Nodes 上运行它，并观察每个步骤。

保存一次 Puppet 运行、一个 Task 或一个 Plan，以便稍后启动——一次或重复启动——其 Nodes 会在每次启动时重新确定。

运行存放在你的模块中的 YAML Plans，支持带类型的参数、在步骤之间传递结果，并且每个 Task 都会依据你的 Node 组进行检查。

OpenVox Console 以容器镜像形式发布，每次 push 都会构建 amd64 和 arm64 版本，同时也提供单个二进制文件。安装指南将带你从一台空主机走到一套可用的部署——openvoxserver、openvoxdb、Postgres 和控制台——可以用容器，也可以用软件包。
