Renouveler la clé de signature des jetons

Remplacez la clé avec laquelle la console signe les jetons de connexion, sans déconnecter personne.

La console signe ses jetons de connexion avec sa propre clé ES256. Chaque jeton nomme la clé qui l'a signé, et la console vérifie les jetons à l'aide d'un ensemble de clés. Une nouvelle clé peut donc prendre le relais pour la signature tandis que les jetons signés par l'ancienne continuent de fonctionner jusqu'à leur expiration : personne n'est déconnecté, et rien ne s'arrête.

Trois paramètres entrent en jeu :

Paramètre Ce que c'est
CONSOLE_RBAC_SIGNING_KEY_FILE la clé avec laquelle cette instance signe
CONSOLE_RBAC_SIGNING_KEY_ID l'ID de la clé, inscrit dans chaque jeton qu'elle signe. Non défini, il vaut default
CONSOLE_RBAC_VERIFICATION_KEYS_DIR un répertoire de clés supplémentaires dont les jetons sont acceptés, un fichier par clé, nommé <key ID>.pem

Une instance accepte toujours les jetons signés avec sa propre clé de signature.

Générer la nouvelle clé

Choisissez-lui un ID ; une date fait un bon choix :

openssl ecparam -genkey -name prime256v1 -noout -out 2026-10-01.pem

Faire accepter les deux clés par chaque instance

Sur chaque instance de la console, placez la clé actuelle et la nouvelle dans son répertoire de vérification, chacune nommée d'après son ID. Un déploiement qui n'a jamais défini CONSOLE_RBAC_SIGNING_KEY_ID utilise default pour la clé actuelle :

sudo install -d -m 0750 -o root -g openvox-console /etc/openvox-console/rbac-verification-keys sudo install -m 0640 -o root -g openvox-console \ /etc/openvox-console/rbac-signing-key.pem /etc/openvox-console/rbac-verification-keys/default.pem sudo install -m 0640 -o root -g openvox-console \ 2026-10-01.pem /etc/openvox-console/rbac-verification-keys/2026-10-01.pem

Définissez CONSOLE_RBAC_VERIFICATION_KEYS_DIR sur ce répertoire si ce n'est pas déjà fait, puis redémarrez chaque instance.

C'est le fait de le faire partout avant que quoi que ce soit ne signe avec la nouvelle clé qui maintient en état de marche un déploiement à répartition de charge : un jeton signé par une instance avec la nouvelle clé est alors accepté par toutes les autres.

Commencer à signer avec la nouvelle clé

Sur les instances qui émettent des jetons (all et web), signez avec la nouvelle clé sous son ID, puis redémarrez-les :

CONSOLE_RBAC_SIGNING_KEY_FILE=/etc/openvox-console/rbac-verification-keys/2026-10-01.pem CONSOLE_RBAC_SIGNING_KEY_ID=2026-10-01

Les nouvelles connexions reçoivent désormais des jetons signés avec la nouvelle clé. Les jetons signés avec l'ancienne continuent de fonctionner, car chaque instance l'accepte toujours.

Retirer l'ancienne clé

Un jeton vit au plus 24 heures : c'est la durée de vie d'un jeton de rafraîchissement. Une fois 24 heures écoulées depuis que la dernière instance a commencé à signer avec la nouvelle clé, retirez le fichier de l'ancienne clé du répertoire de vérification de chaque instance, puis redémarrez-les. Les jetons signés avec l'ancienne clé sont dès lors refusés.

Retirer l'ancienne clé plus tôt déconnecte tous ceux dont elle a signé les jetons. La retirer puis perdre la nouvelle clé déconnecte tout le monde. Sauvegardez la nouvelle clé avant de retirer l'ancienne.
