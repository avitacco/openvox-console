Nodes

Tenir les agents de Node à jour

Comment la console met à jour d'elle-même l'agent de Node sur vos Nodes, comment voir quels Nodes sont en retard, et l'étape unique pour les Nodes installés avant l'existence de cette fonctionnalité.

L'agent de Node est le petit service que le script d'installation place sur chaque Node. Il détient la connexion du Node à la console et effectue les exécutions et les Tasks que vous lancez. Il est construit avec la console et livré à l'intérieur de celle-ci : une console plus récente apporte donc généralement un agent de Node plus récent.

La console met à jour pour vous l'agent de Node sur vos Nodes. Lorsqu'un Node se connecte, la console demande quel build de l'agent il exécute. Si ce build est plus ancien que celui que fournit la console, celle-ci demande au Node de se mettre à jour, et le Node télécharge le nouveau build depuis la console, le vérifie, l'installe et redémarre dessus. Vous n'avez rien à faire sur le Node.

Ce que vous voyez

  • Page Nodes. Un Node dont l'agent est en retard est marqué Client obsolète.
  • La page d'un Node. Affiche la version de l'agent et sa date de construction, s'il est à jour, et l'issue de la dernière tentative de mise à jour.
  • Dashboard. Sous État du parc, le nombre d'agents de Node à jour, le nombre d'agents obsolètes, le nombre de mises à jour en échec, et l'activation ou non des mises à jour automatiques.

Lancer vous-même une mise à jour, depuis la page d'un Node, nécessite nodes:manage sur un rôle dont les groupes de Nodes incluent le Node. Les mises à jour que la console lance d'elle-même ne sont limitées par les groupes de Nodes de personne.

Un Node qui ne s'est pas connecté depuis la mise à jour de la console apparaît comme n'ayant pas encore remonté d'information, et non comme obsolète. Il le fera à sa prochaine connexion.

Les Nodes installés avant l'existence des mises à jour automatiques

Un agent de Node antérieur à cette fonctionnalité ne peut pas se mettre à jour lui-même, car il ne comprend pas la demande. La console affiche un tel Node comme obsolète, avec une note indiquant qu'il faut relancer le script d'installation. Exécutez-le une fois sur le Node, exactement comme pour ajouter le Node :

Linuxcurl -fsSL https://console.example.com/packages/install.sh | sudo bash macOScurl -fsSL https://console.example.com/packages/install-macos.sh | sudo bash WindowsInvoke-WebRequest https://console.example.com/packages/install.ps1 -OutFile install.ps1 .\install.ps1

À partir de là, le Node se tient lui-même à jour. Le Dashboard compte les Nodes qui attendent encore cette opération, pour que vous sachiez quand vous les avez tous traités.

Si vous gérez plutôt le paquet Linux avec Puppet, ensure => latest sur le paquet node-agent-client issu du dépôt de la console fait le même travail.

Ce que fait et ne fait pas une mise à jour

  • Elle n'interrompt jamais le travail. Un Node en pleine exécution ou en plein Task est laissé tranquille, et une nouvelle tentative a lieu une minute plus tard.
  • Elle est vérifiée avant d'être installée. La console envoie la somme de contrôle attendue du téléchargement par la connexion authentifiée du Node. Le Node refuse tout ce qui ne correspond pas, et démarre une fois le nouvel agent pour confirmer qu'il fonctionne avant de remplacer l'ancien. Si l'une ou l'autre vérification échoue, le Node conserve son agent actuel.
  • Elle procède quelques Nodes à la fois. Au plus 20 Nodes se mettent à jour en même temps, quel que soit le nombre de Nodes en retard.
  • Elle ne fait qu'avancer. Un Node dont l'agent est plus récent que celui que fournit la console est laissé tel quel. C'est ce que vous observez en pleine mise à jour d'un cluster d'instances de la console, ou après un retour à une version antérieure de la console.
  • Sous Linux, elle passe par le gestionnaire de paquets. Le Node installe le .deb ou le .rpm de la console ; dpkg et rpm indiquent donc la version réellement installée.

Les mises à jour sous macOS et Windows sont couvertes par les tests du projet, mais n'ont pas encore été exécutées de bout en bout sur de vrais hôtes macOS et Windows. Signalez tout ce qui ne se déroule pas comme décrit ici.

Quand une mise à jour échoue

La page du Node affiche la raison, dans les termes du Node lui-même : le téléchargement a échoué, la somme de contrôle ne correspondait pas, le gestionnaire de paquets était occupé. La console réessaie au bout de cinq minutes, puis attend deux fois plus longtemps à chaque fois, et s'arrête après cinq échecs sur le même build.

La cause la plus fréquente est un Node qui ne peut pas joindre l'URL de base de la console (CONSOLE_BASE_URL), d'où il télécharge le nouvel agent. Le script d'installation utilisait la même adresse : vérifiez donc ce qui a changé depuis l'installation du Node.

Une fois la cause corrigée, choisissez Mettre à niveau le client sur la page du Node pour réessayer immédiatement. Cela nécessite la permission nodes:manage et un Node connecté. Cela fonctionne que les mises à jour automatiques soient activées ou non, et même après l'arrêt des tentatives automatiques.

La console reprend aussi d'elle-même lorsque vous la mettez à jour vers une version qui fournit un agent de Node différent.

Désactiver les mises à jour automatiques

Pour empêcher la console de mettre à jour d'elle-même les agents de Node, définissez ceci sur chaque instance de la console et redémarrez-la :

CONSOLE_AGENT_AUTO_UPGRADE=false

La console enregistre toujours le build de l'agent de chaque Node et affiche toujours les Nodes obsolètes. Mettre à niveau le client sur la page d'un Node fonctionne toujours.

Pour exempter plutôt un seul Node, définissez NODE_AGENT_ACCEPT_UPGRADES=false pour l'agent de Node de ce Node et redémarrez-le :

Plateforme Où la définir
Linux Ajoutez la ligne à /etc/node-agent-client/local.env, puis exécutez sudo systemctl restart node-agent-client
Windows Définissez-la comme variable d'environnement système, puis redémarrez le service node-agent-client
macOS Ajoutez-la à EnvironmentVariables dans /Library/LaunchDaemons/org.voxpupuli.node-agent-client.plist, puis rechargez le job launchd

La page du Node indique alors que les mises à jour sont refusées sur ce Node, et la console n'essaie pas. Sous macOS, relancer le script d'installation réécrit ce fichier : redéfinissez donc la variable ensuite.
