क़दम-दर-क़दम: कंसोल इंस्टॉल कीजिए, अपने Nodes जोड़िए, उसका विस्तार कीजिए, और रोज़मर्रा में उसे चलाइए। हर कमांड ठीक वैसी ही दिखाई गई है जैसी आप टाइप करते हैं।

इंस्टॉल

आप क्या बना रहे हैं, शुरू करने से पहले कौन-से नाम तय करने हैं, और किस इंस्टॉल गाइड का पालन करना है।

openvoxserver, openvoxdb, दोनों डेटाबेस और कंसोल को Docker Compose से चलाइए — खाली होस्ट से Nodes के लिए तैयार कंसोल तक।

openvoxserver, openvoxdb और Postgres को पैकेजों से इंस्टॉल कीजिए, कंसोल build कीजिए, और उसे systemd सेवा के रूप में चलाइए।

Nodes

Linux, macOS या Windows पर एक स्क्रिप्ट से Node को नामांकित कीजिए, उसके प्रमाणपत्र पर हस्ताक्षर कीजिए, और उसे कनेक्ट होते और चलते देखिए।

कंसोल से Node प्रमाणपत्रों पर हस्ताक्षर कीजिए, उन्हें निरस्त और साफ़ कीजिए — और जानिए कि हर कार्रवाई कनेक्टेड Node पर क्या असर डालती है।

कंसोल से किसी Node को हटाइए — इससे openvoxdb और CA में क्या होता है, और क्या बना रहता है।

कंसोल आपके Nodes पर Node एजेंट को स्वयं कैसे अपग्रेड करता है, कैसे देखें कि कौन-से Nodes पीछे हैं, और इस सुविधा से पहले इंस्टॉल हुए Nodes के लिए एक बार का क़दम।

विस्तार

कंसोल का हर run mode क्या देता है और क्या चलाता है, और हर एक के लिए क्या कॉन्फ़िगर करना ज़रूरी है।

दूसरे कंसोल इंस्टेंस को cluster में जोड़िए, इंस्टेंसों को run modes में बाँटिए, और वर्गीकरण को compilers के पास रखिए।

उपयोग

Facts से मेल खाने वाले या नाम से पिन किए गए Node समूहों के एक वृक्ष से तय कीजिए कि हर Node को कौन-सी क्लासें, पैरामीटर और Environment मिलें।

एक या अधिक control रिपॉज़िटरी से Puppet कोड उन Environments में deploy कीजिए जिनसे openvoxserver संकलन करता है।

माँग पर Puppet या कोई Puppet Task चलाइए — एक Node पर, किसी चयन पर, किसी क्वेरी से मेल खाने वाले Nodes पर, या किसी Node समूह पर — और देखिए कि हर Node ने क्या किया।

एक Plan बनाइए - क्रम से पूरे होने वाले Puppet रनों और Tasks की सूची - उसे सहेजिए, अपने चुने Nodes पर चलाइए, और हर चरण पर नज़र रखिए।

किसी Puppet रन, Task या Plan को बाद में शुरू होने के लिए सहेजिए, एक बार या बार-बार, ऐसे Nodes पर जिनका हिसाब हर बार शुरू होते समय लगाया जाता है।

भूमिकाओं और अनुमतियों के ज़रिये लोगों को पहुँच दीजिए, अपने पहचान प्रदाता से साइन इन कीजिए, और प्रोग्रामों के लिए टोकन जारी कीजिए।

कमज़ोरी प्रदाता सेट अप कीजिए, फ़्लीट के निष्कर्ष पढ़िए, और जानिए कि हर प्रदाता क्या देख सकता है और क्या नहीं।

Linux Nodes को लंबित पैकेज अपडेट के लिए स्कैन कीजिए, फिर उन्हें ड्राई रन, रुकने की सीमा और वैकल्पिक रीबूट के साथ बैचों में पैच कीजिए।

उन होस्टों को पंजीकृत कीजिए जिन तक कंसोल SSH से पहुँचता है, उनकी host keys पिन कीजिए, उन्हें जाँचिए, और उन पर किसी भी अन्य Node की तरह Tasks चलाइए।

अपने modules में रखे YAML Plans चलाइए, typed पैरामीटरों के साथ, चरणों के बीच पहुँचाए गए परिणामों के साथ, और हर Task को आपके Node समूहों के विरुद्ध जाँचते हुए।

किसी AI एजेंट को उसका अपना सीमित टोकन दीजिए, उसे फ़्लीट पढ़ने और बदलाव माँगने दीजिए, और कुछ भी चलने से पहले हर बदलाव को स्वयं स्वीकृत कीजिए।

संचालन

streaming-replication standby को promote करके कंसोल के डेटाबेस के खो जाने से उबरिए।

जिस कुंजी से कंसोल लॉगिन टोकनों पर हस्ताक्षर करता है, उसे किसी को लॉग आउट किए बिना बदलिए।

कंटेनर परिनियोजन के दोनों डेटाबेस को dump और restore करके Postgres 17 से 18 पर ले जाइए।

OpenVox Console कंटेनर इमेजों के रूप में आता है, जो हर push पर amd64 और arm64 के लिए बनती हैं, और एक अकेली बाइनरी के रूप में भी। इंस्टॉल गाइड आपको खाली होस्ट से एक चालू परिनियोजन तक ले जाते हैं - openvoxserver, openvoxdb, Postgres और कंसोल - कंटेनरों से या पैकेजों से।
