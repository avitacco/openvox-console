संचालन

टोकन हस्ताक्षर कुंजी बदलें

जिस कुंजी से कंसोल लॉगिन टोकनों पर हस्ताक्षर करता है, उसे किसी को लॉग आउट किए बिना बदलिए।

कंसोल अपने लॉगिन टोकनों पर अपनी ES256 कुंजी से हस्ताक्षर करता है। हर टोकन उस कुंजी का नाम बताता है जिसने उस पर हस्ताक्षर किए, और कंसोल टोकनों को कुंजियों के एक समुच्चय से जाँचता है। इसलिए नई कुंजी हस्ताक्षर का काम सँभाल सकती है, जबकि पुरानी कुंजी से हस्ताक्षरित टोकन अपनी समाप्ति तक काम करते रहते हैं: कोई लॉग आउट नहीं होता, और कुछ नहीं रुकता।

तीन सेटिंग्स शामिल हैं:

सेटिंग यह क्या है
CONSOLE_RBAC_SIGNING_KEY_FILE वह कुंजी जिससे यह इंस्टेंस हस्ताक्षर करता है
CONSOLE_RBAC_SIGNING_KEY_ID कुंजी की ID, जो उसके द्वारा हस्ताक्षरित हर टोकन में लिखी जाती है। सेट न होने पर यह default होती है
CONSOLE_RBAC_VERIFICATION_KEYS_DIR अतिरिक्त कुंजियों की एक डायरेक्टरी जिनसे हस्ताक्षरित टोकन स्वीकार किए जाएँ, हर कुंजी के लिए एक फ़ाइल, जिसका नाम <key ID>.pem हो

कोई इंस्टेंस अपनी हस्ताक्षर कुंजी से हस्ताक्षरित टोकन हमेशा स्वीकार करता है।

नई कुंजी बनाएँ

इसके लिए एक ID चुनिए; तारीख़ एक अच्छा विकल्प है:

openssl ecparam -genkey -name prime256v1 -noout -out 2026-10-01.pem

हर इंस्टेंस से दोनों कुंजियाँ स्वीकार करवाएँ

हर कंसोल इंस्टेंस पर, मौजूदा कुंजी और नई कुंजी को उसकी verification डायरेक्टरी में रखिए, हर एक का नाम उसकी ID पर। जिस परिनियोजन ने कभी CONSOLE_RBAC_SIGNING_KEY_ID सेट नहीं किया, वह मौजूदा कुंजी के लिए default का उपयोग करता है:

sudo install -d -m 0750 -o root -g openvox-console /etc/openvox-console/rbac-verification-keys sudo install -m 0640 -o root -g openvox-console \ /etc/openvox-console/rbac-signing-key.pem /etc/openvox-console/rbac-verification-keys/default.pem sudo install -m 0640 -o root -g openvox-console \ 2026-10-01.pem /etc/openvox-console/rbac-verification-keys/2026-10-01.pem

यदि पहले से सेट नहीं है, तो CONSOLE_RBAC_VERIFICATION_KEYS_DIR को उस डायरेक्टरी पर सेट कीजिए, और हर इंस्टेंस को पुनः आरंभ कीजिए।

नई कुंजी से कुछ भी हस्ताक्षरित होने से पहले यह हर जगह कर लेना ही load-balanced परिनियोजन को चालू रखता है: तब एक इंस्टेंस द्वारा नई कुंजी से हस्ताक्षरित टोकन हर दूसरे इंस्टेंस द्वारा स्वीकार किया जाता है।

नई कुंजी से हस्ताक्षर शुरू करें

टोकन जारी करने वाले इंस्टेंसों (all और web) पर, नई कुंजी से उसकी ID के तहत हस्ताक्षर कीजिए, और उन्हें पुनः आरंभ कीजिए:

CONSOLE_RBAC_SIGNING_KEY_FILE=/etc/openvox-console/rbac-verification-keys/2026-10-01.pem CONSOLE_RBAC_SIGNING_KEY_ID=2026-10-01

अब नए लॉगिन को नई कुंजी से हस्ताक्षरित टोकन मिलते हैं। पुरानी कुंजी से हस्ताक्षरित टोकन काम करते रहते हैं, क्योंकि हर इंस्टेंस अब भी उसे स्वीकार करता है।

पुरानी कुंजी को सेवानिवृत्त करें

कोई टोकन अधिकतम 24 घंटे जीवित रहता है: refresh टोकन इतने ही समय तक चलता है। अंतिम इंस्टेंस के नई कुंजी से हस्ताक्षर शुरू करने के 24 घंटे बीत जाने पर, हर इंस्टेंस की verification डायरेक्टरी से पुरानी कुंजी की फ़ाइल हटाइए, और उन्हें पुनः आरंभ कीजिए। उसके बाद पुरानी कुंजी से हस्ताक्षरित टोकन अस्वीकार कर दिए जाते हैं।

पुरानी कुंजी को पहले हटा देने से वे सभी लॉग आउट हो जाते हैं जिनके टोकन पर उसने हस्ताक्षर किए थे। उसे हटाकर फिर नई कुंजी खो देने से सभी लॉग आउट हो जाते हैं। पुरानी कुंजी को हटाने से पहले नई कुंजी का बैकअप लीजिए।
नई कुंजी बनाएँ हर इंस्टेंस से दोनों कुंजियाँ स्वीकार करवाएँ नई कुंजी से हस्ताक्षर शुरू करें पुरानी कुंजी को सेवानिवृत्त करें

OpenVox Console कंटेनर इमेजों के रूप में आता है, जो हर push पर amd64 और arm64 के लिए बनती हैं, और एक अकेली बाइनरी के रूप में भी। इंस्टॉल गाइड आपको खाली होस्ट से एक चालू परिनियोजन तक ले जाते हैं - openvoxserver, openvoxdb, Postgres और कंसोल - कंटेनरों से या पैकेजों से।
