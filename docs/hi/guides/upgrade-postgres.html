संचालन

कंटेनर डेटाबेस को Postgres 18 पर अपग्रेड करें

कंटेनर परिनियोजन के दोनों डेटाबेस को dump और restore करके Postgres 17 से 18 पर ले जाइए।

प्रोडक्शन compose फ़ाइल दोनों डेटाबेस Postgres 18 पर चलाती है। Postgres 18 इमेज अपना डेटा volume के भीतर संस्करण-क्रमांकित डायरेक्टरी में रखती हैं, इसलिए volumes पहले की तरह /var/lib/postgresql/data पर नहीं, बल्कि /var/lib/postgresql पर माउंट होते हैं।

Postgres 17 का डेटा रखने वाले volume पर शुरू किया गया Postgres 18 कंटेनर शुरू होने से मना कर देता है, एक ऐसी त्रुटि के साथ जो Error: in 18+, these Docker images are configured to store database data in a format which is compatible with "pg_ctlcluster" से शुरू होती है। यह इनकार है, क्षति नहीं: पुराना डेटा अछूता रहता है। यह गाइड उसे नए संस्करण में ले जाता है।

अपग्रेड एक dump और restore है: pg_upgrade के लिए एक ही इमेज में दोनों संस्करण चाहिए होते, और इन इमेजों में एक ही होता है।

दोनों डेटाबेस का dump लें

यह Postgres 17 कंटेनरों के चलते रहते ही कीजिए। जो उनमें लिखता है उसे रोकिए, और डेटाबेस चालू रहने दीजिए:

docker compose -f docker-compose.yml stop console openvoxdb docker compose -f docker-compose.yml exec -T openvoxdb-postgres \ pg_dumpall -U openvoxdb > openvoxdb-17.sql docker compose -f docker-compose.yml exec -T console-postgres \ pg_dumpall -U console > console-17.sql

आगे बढ़ने से पहले जाँचिए कि दोनों फ़ाइलें मौजूद हैं और खाली नहीं हैं:

ls -l openvoxdb-17.sql console-17.sql

volumes बदलें

यह Postgres 17 का डेटा हटा देता है। यहाँ से दोनों dump फ़ाइलें ही एकमात्र प्रति हैं, इसीलिए ऊपर वाली जाँच पहले आती है।

 docker compose -f docker-compose.yml down docker volume rm openvox-console_openvoxdb-postgres-data openvox-console_console-postgres-data

volumes के नाम प्रोजेक्ट डायरेक्टरी के नाम पर होते हैं; उन्हें docker volume ls से जाँचिए।

Postgres 18 पर restore करें

केवल डेटाबेस शुरू कीजिए। वे खाली शुरू होते हैं, और openvoxdb वाले डेटाबेस को उसकी ज़रूरत का pg_trgm extension compose फ़ाइल से मिलता है:

docker compose -f docker-compose.yml up -d openvoxdb-postgres console-postgres docker compose -f docker-compose.yml exec -T openvoxdb-postgres \ psql -U openvoxdb < openvoxdb-17.sql docker compose -f docker-compose.yml exec -T console-postgres \ psql -U console < console-17.sql

फिर बाक़ी सब कुछ शुरू कीजिए:

docker compose -f docker-compose.yml up -d

यदि openvoxdb कहे कि pg_trgm नहीं है

openvoxdb pg_trgm extension के बिना शुरू होने से मना कर देता है। compose फ़ाइल इसे केवल तब जोड़ती है जब डेटाबेस पहली बार बनता है, इसलिए पहले से मौजूद डेटाबेस में इसे हाथ से जोड़ना होगा:

docker compose -f docker-compose.yml exec openvoxdb-postgres \ psql -U openvoxdb -c 'CREATE EXTENSION IF NOT EXISTS pg_trgm;'

Postgres 17 पर बने रहना

17 पर बने रहने के लिए एक नहीं, दो बदलाव चाहिए: OPENVOXDB_POSTGRES_VERSION=17-alpine सेट कीजिए (और कंसोल का समकक्ष, CONSOLE_POSTGRES_VERSION), और हर volume के mount को वापस /var/lib/postgresql/data पर ले जाइए। केवल संस्करण बदलने से ऊपर वाली त्रुटि आती है।

दोनों डेटाबेस का dump लें volumes बदलें Postgres 18 पर restore करें यदि openvoxdb कहे कि pg_trgm नहीं है Postgres 17 पर बने रहना

OpenVox Console कंटेनर इमेजों के रूप में आता है, जो हर push पर amd64 और arm64 के लिए बनती हैं, और एक अकेली बाइनरी के रूप में भी। इंस्टॉल गाइड आपको खाली होस्ट से एक चालू परिनियोजन तक ले जाते हैं - openvoxserver, openvoxdb, Postgres और कंसोल - कंटेनरों से या पैकेजों से।
