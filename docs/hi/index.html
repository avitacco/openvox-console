Nodes वर्गीकरण Code ऑर्केस्ट्रेशन सुरक्षा पहुँच नियंत्रण

हर Node देखिए, तय कीजिए कि क्या कहाँ चले, अपना कोड deploy कीजिए, और जो लौटकर आए उस पर कार्रवाई कीजिए। OpenVox के लिए एक Puppet Enterprise कंसोल — एक Go बाइनरी, उन्हीं openvox-server और openvoxdb के ऊपर जिन्हें आप पहले से चला रहे हैं।

देखिए यह क्या करता है GitHub से प्राप्त कीजिए

यह क्या करता है

नीचे का हर पृष्ठ स्वयं कंसोल दिखाता है, एक चालू इंस्टेंस से लिया गया।

हर Node, उसने अंतिम बार क्या बताया, वह पहुँच में है या नहीं, और उसके प्रमाणपत्र की स्थिति। नियम-आधारित Node समूह जो तय करते हैं कि कौन-सा कॉन्फ़िगरेशन कहाँ लागू हो। एक या कई control रिपॉज़िटरी से Puppet कोड भेजिए, माँग पर या webhook से। पूरे फ़्लीट पर Puppet, Tasks और Plans चलाइए, और देखिए कि हर Node ने क्या किया। हर जगह क्या स्थापित है, और कौन-सी सलाहें उसे प्रभावित करती हैं। भूमिकाएँ, सेवा टोकन, और किसने क्या बदला इसका रिकॉर्ड।

चलाने के लिए एक ही बाइनरी

कंसोल, पहुँच नियंत्रण, वर्गीकरण, ऑर्केस्ट्रेशन और कोड deploy — सब एक ही प्रक्रिया हैं। आपस में जोड़ने को कुछ नहीं, तालमेल में रखने के लिए कोई आंतरिक सेवाएँ नहीं, और उन्नयन के लिए बस एक चीज़।

यह उसी स्टैक के ऊपर बैठता है जो आपके पास पहले से है। openvox-server अब भी कैटलॉग संकलित करता है और CA चलाता है; openvoxdb अब भी Facts और Reports रखता है। आपके एजेंट ठीक उसी से बात करते रहते हैं जिससे अभी करते हैं — कंसोल मानक ENC अनुबंध देता है, इसलिए Node की ओर बदलने को कुछ नहीं है।

docker compose up openvoxserver, openvoxdb, Postgres और कंसोल को एक साथ चालू कर देता है, ताकि आप एक परीक्षण एजेंट उस पर लगाकर अपने अपने Nodes को प्रकट होते देख सकें — किसी भी प्रतिबद्धता से पहले।

OpenVox Console दो कंटेनर इमेज के रूप में आता है, हर push पर amd64 और arm64 के लिए बनाया जाता है। SETUP.md एक वास्तविक परिनियोजन से होकर ले जाता है — openvoxserver, openvoxdb, Postgres और कंसोल — कंटेनर और पैकेज दोनों के निर्देशों के साथ।
