使う

Jobs をスケジュールする

Puppet run、Task、Plan を保存して後で開始します。一度だけでも繰り返しでも、開始のたびに割り出される Node に対して実行されます。

スケジュールは、自動で開始するよう保存された Puppet run、Task、または Plan です: 指定した時刻に一度だけ、または繰り返し開始します。その時点で同じ Job を手動で開始した場合と同じことを行い (Jobs を実行するを参照)、開始のたびに他と同様の Job として記録されます。

スケジュールの作成と変更には orchestrator:run が、閲覧には orchestrator:read が必要です。

スケジュールを作成する

Jobs、スケジュールされた Jobs、新しいスケジュールの順に開きます。または、任意の場所で Puppet を実行、Task を実行、Plan を実行に入力して代わりにスケジュールを選ぶと、入力した内容が入った同じフォームが開きます。Node グループのページからこれを行うと、現時点でそこに含まれる Node ではなく、グループ自体がスケジュールされます。

  1. 名前を付けます。スケジュールが開始する Jobs にはこの名前のラベルが付きます。
  2. 実行する内容を選びます: Puppet (必要なら実行オプション付き)、パラメーター付きの Task、または保存された Plan から選んだ Plan。
  3. 対象の Nodes を選びます: Node を選ぶと同様に、一覧、クエリ、または Node グループ。Nodes をプレビューで、現時点で何に対して実行されるかを確認できます。
  4. 日時を選びます: 開始時刻と、繰り返す場合はその頻度。
  5. スケジュールを保存。

コンソールは、スケジュールを保存する際、今すぐ Job を開始した場合とまったく同じように検査し、誤っている部分の横に理由を示して拒否します。違いが 1 つあります: まだどの Node にも一致しないクエリやグループでも保存できます。

Node は毎回割り出される

クエリや Node グループは、スケジュールが開始するたびに改めて評価されます。来週グループに加わった Node は来週から含まれ、クエリに一致しなくなった Node は除外されます。

時刻と繰り返し

時刻は、フォームに表示されるブラウザーのタイムゾーンで入力・表示されます。別のタイムゾーンにいる人には、同じ瞬間がその人のタイムゾーンで表示されます。

繰り返さないスケジュールは一度だけ開始し、その後は完了と表示されます。繰り返しのスケジュールは開始時刻に開始し、その後は指定した分、時間、日、週ごとに開始します。最短の繰り返し間隔は 5 分です。

繰り返しの間隔は固定の長さです: 1 日は 24 時間、1 週間はその 7 倍です。夏時間で時計が変わる地域では、毎日のスケジュールは UTC で時刻を保つため、現地時刻では 1 時間ずれます。「第 1 月曜日」のような暦に基づくルールはありません。

繰り返しのスケジュールには過去の開始時刻を指定できます。その場合、次に開始するのはまだ到来していない最初の繰り返しの時刻です。

スケジュールの実行主体

スケジュールは所有者 (最後に保存した人) として実行されます。開始のたびに、コンソールは保存時点ではなく、その時点での所有者のロールを適用します:

  • 所有者が Jobs を実行できなくなった場合 (ロールが削除された、アカウントやサービストークンが削除されたなど)、何も開始されません。
  • 所有者のロールが特定の Node グループに対して付与されている場合、クエリやグループで得られるのは、それらのグループ内の一致する Node です。一覧で指定した Node はすべてそれらのグループ内にまだ含まれている必要があり、そうでなければ何も開始されません。
  • 所有者のロールが一部の Task に限定されている場合、スケジュールが開始するのは所有者がまだ実行できる Task だけで、それも実行できる Node に対してだけです。実行できない Task のスケジュールを保存しようとすると、その Task を示して拒否されます。

スケジュールへの変更を保存すると、自分がその所有者になります。他の人のスケジュールを開くと、フォームにその旨が表示されます。退職した人からスケジュールを引き継ぐにはこの方法を使います: 開いて保存するだけです。一時停止と再開では所有者は変わりません。

自分が所有するスケジュールは閲覧・変更できます。All Nodes に対してロールが付与されている人は、全員のスケジュールを閲覧・変更できます。ユーザー、ロール、トークンを参照してください。

スケジュールが開始しない場合

スケジュールのページには、予定時刻が来るたびに何が起きたかが一覧表示されます。

結果 意味
開始 Job が開始されました。その行は Job にリンクしています。
スキップ 表示された理由により、何も開始されませんでした。スケジュールは次の時刻から続行されます。
未実行 予定時刻にスケジューラーを動かしているコンソールがなく、動き出した時点で 15 分以上遅れていました。
中断 開始しようとしていたコンソールインスタンスが、開始する前に停止しました。

スケジュールは次の場合にスキップされます:

  • クエリやグループがどの Node にも、または所有者が操作できるどの Node にも一致しない。
  • 所有者が Jobs を実行できなくなった、または指定された Node が所有者の Node グループから外れた。
  • その Task、または Plan の Task のいずれかが、所有者のロールでもう許可されていない (発火には Task と、Plan の場合はステップが示されます)。ロールを一部の Task に限定するを参照してください。
  • その Task、Task パラメーター、Environment、Node グループが、スケジュールの記述どおりにはもう存在しない。
  • Node や Task を割り出すための openvoxdb や Puppet サーバーに到達できなかった。
  • 前回開始した Job がまだ実行中である。

開始されなかった発火が再試行されることはありません。02:00 に予定された実行が、コンソールが夜間停止していたために 09:00 に開始されることはなく、1 回の予定時刻に Task が 2 回開始されることもありません。繰り返しのスケジュールが複数回分逃した場合は、未実行の発火が 1 件記録され、次の時刻から再開されます。

スキップされた発火と未実行の発火はアクティビティページにも記録され、スケジュールされた Jobs の一覧には各スケジュールの最後の結果が表示されます。

スケジュールの開始時に接続していない Node は、手動で開始した Job と同様に、その Job の中で「agent not connected」で失敗します。Job は他の Node に対しては引き続き開始されます。

スケジュールされた Plan は独自のステップを保持する

Plan を選ぶと、スケジュールはそのステップのコピーを取って表示します。それ以降、スケジュールはそのコピーを実行します。保存された Plan を変更または削除しても、スケジュールが実行する内容は変わりません。

Plan への変更を反映するには、スケジュールを編集し、Plan で Plan を選び直して保存します。Plan を「下に表示されているステップを維持」のままにすると、コピーはそのまま保持されます。

その理由は、スケジュールは所有者のアクセス権で実行される一方、Jobs を実行できる全員が Plan を変更できるからです。Plans を実行するを参照してください。

スケジュールの予定時刻になったときにステップが実行できなくなっている場合 (たとえば、その Task がコードから削除された場合)、何も開始されず、その時刻はそのステップを示してスキップとして記録されます。

スケジュールを一時停止、変更、削除する

スケジュールのページで:

  • 一時停止はスケジュールの発火を止めます。再開は、まだ到来していない次の時刻から再び動かします。過ぎた時刻の分は何も開始されません。繰り返さないスケジュールで、一時停止中にその時刻が過ぎた場合は、代わりに新しい開始時刻が必要です。
  • 編集はフォームを開きます。保存すると、新しいスケジュールとして再び検査されます。
  • 削除はスケジュールを削除します。それが開始した Jobs は Job 履歴に残り、引き続きそのスケジュール名が示されます。

Node グループを削除しても、それを対象とするスケジュールは削除されません。それらは、変更または削除するまで、グループがもう存在しない旨を示してスキップされます。

機密の Task パラメーター

sensitive とマークされた Task パラメーター (パスワードやトークン) は、スケジュールが開始するまで保持しておく必要があります。コンソールはそれをシークレット鍵で暗号化して保存し、スケジュールやその Jobs が表示されるすべての場所で Sensitive [value redacted] と表示します。スケジュールされた Plan の Task ステップの機密値も同様で、スケジュールのフォームでは各ステップの下でそれらを入力します。

  • シークレット鍵がない場合、機密の値を持つスケジュールは拒否されます。コンソールを提供する、またはスケジューラーを実行するすべてのインスタンスで CONSOLE_SECRETS_KEY_FILE を設定してください。同じ鍵を使う脆弱性を追跡するを参照してください。
  • 自分のスケジュールを編集するとき、保存された値を維持するには機密フィールドを空のままにします。
  • 他の人のスケジュールを保存するときは、機密の値を入力し直す必要があります。コンソールは保存されたシークレットを新しい所有者に引き渡しません。
  • シークレット鍵が変わると、保存された値は読めなくなります。スケジュールは、値を入れて再び保存されるまで、その旨を示してスキップされます。

API から

curl -X POST https://console.example.com/api/v1/orchestrator/schedules \ -H "Authorization: Bearer <access token>" \ -H 'Content-Type: application/json' \ -d '{"name":"Weekly no-op", "kind":"run", "options":{"noop":true}, "group":12, "startAt":"2026-01-04T03:00:00Z", "repeat":{"every":1,"unit":"week"}}'

kind は run (options を伴う)、task (Task のリクエストと同様に task、params、environment、timeoutSeconds を伴う)、または plan (Plan のリクエストと同様に planName と steps を伴う) のいずれかです。Node は targets、query、group で指定します。repeat.unit は minute、hour、day、week のいずれかです。一度だけ開始するスケジュールでは repeat を省略します。

リクエスト 内容
GET /api/v1/orchestrator/schedules 閲覧できるスケジュールを一覧表示する
GET /api/v1/orchestrator/schedules/<id> 1 つのスケジュールを、予定時刻ごとに起きたことと合わせて返す
PUT /api/v1/orchestrator/schedules/<id> スケジュールを置き換え、自分を所有者にする
POST /api/v1/orchestrator/schedules/<id>/pause と /resume 一時停止または再開する
DELETE /api/v1/orchestrator/schedules/<id> スケジュールを削除する

拒否されたリクエストは 400 (自分の Node グループ外の Node の場合は 403) で応答し、error と、スケジュールのどの部分に関するものかを示す field、そして Plan の場合は拒否された step を含みます。サービストークンが所有するスケジュールは、そのトークンが存在し orchestrator:run を持つ限り実行されます。

スケジュールが開始される場所

スケジュールは all と orchestrator の実行モードのインスタンスによって開始されます。複数が動いている場合、各予定時刻はそのうちのちょうど 1 つによって開始されます。

スケジュールを作成する Node は毎回割り出される 時刻と繰り返し スケジュールの実行主体 スケジュールが開始しない場合 スケジュールされた Plan は独自のステップを保持する スケジュールを一時停止、変更、削除する 機密の Task パラメーター API から スケジュールが開始される場所

OpenVox Console は、push のたびに amd64 と arm64 向けにビルドされるコンテナイメージと、単一のバイナリとして提供されます。インストールガイドでは、コンテナまたはパッケージを使って、空のホストから openvoxserver、openvoxdb、Postgres、コンソールからなる稼働するデプロイまでを案内します。
