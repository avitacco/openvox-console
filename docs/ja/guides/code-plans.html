コード内の Plan を実行する

モジュール内にある YAML の Plan を、型付きのパラメーター、ステップ間での結果の受け渡し、Node グループに照らしたすべての Task の検査とともに実行します。

コード Plan は、モジュールの plans ディレクトリにある YAML ファイルで、Bolt と Puppet Enterprise が使う形式です。コンソールは deploy したコードからそれを読み込み、自ら実行します: ステップを 1 つずつ順に、結果をステップからステップへ渡しながら。Bolt も Puppet 言語も必要ありません。

これは保存された Plan とは異なります。保存された Plan はコンソールで組み立てた Puppet run と Task の固定された一覧で、1 組の Node に対して実行されます。コード Plan はコードとともに存在し、独自のパラメーターを受け取り、前のステップから各ステップの対象を決めます。

Plans の一覧の閲覧には orchestrator:read が、実行には orchestrator:run が必要です。新しい権限は関係しません。

Plan の取得元

コンソールは各 Environment のモジュールの中から、environment.conf の modulepath の順序で (なければ modules)、<module>/plans/<name>.yaml を探します。Plan の名前は module::name、init.yaml の場合は単に module です。同じ名前が 2 つのディレクトリにある場合は、Puppet と同様に最初のものが優先されます。

ファイルは、コードを deploy するコンソールインスタンスのコードディレクトリ (CONSOLE_CODE_DIR_PATH) から読み込まれます。deploy されたコードを持たないインスタンスは、Plans を一覧表示することも実行することもできず、空の一覧を表示するのではなくその旨を示します。Plans は deploy を行うインスタンスから実行してください。

Jobs、Plans の順に開きます: コード内のプランセクションに Environment の Plans が一覧表示されます。コンソールが実行できない Plan は、ステップを示した理由とともに一覧表示されます。

Plan にできること

Plan には description、parameters、steps、return があります:

description: Restart a service, then check it parameters: targets: type: TargetSpec description: Where to restart it service: type: String[1] default: nginx token: type: Optional[Sensitive[String]] steps: - name: restart description: Restart the service task: service::restart targets: $targets parameters: name: $service - name: status task: service::status targets: $restart.ok_targets parameters: name: $service - message: "checked ${status.targets}" return: restarted: $restart.ok_targets healthy: $status.ok

パラメーターは type、任意の default、description を宣言します。型は Task で使うもの (String、Integer[1, 10]、Boolean、Array[String]、Enum['a','b']、Optional[...] など) に加え、TargetSpec (Node) と Sensitive[...] です。既定値がなく Optional でもないパラメーターは必須です。パラメーターが不足している、未知である、または型が誤っている実行は、何かが始まる前に、そのパラメーターを示してコンソールが拒否します。

ステップは次のいずれか 1 つだけを行います:

  • task: module::task と targets、parameters。Task を実行します。
  • plan: module::plan と parameters。この Plan の一部として別の Plan を実行します。Plan は 5 階層まで Plan を呼び出せますが、自分自身を呼び出すことはできません。
  • message: text。テキストを実行の記録に出力します。

ステップには name を付けることができ、これによりその結果を後続のステップで $name として利用できます。description も付けられます。

参照は $name、$name.field、$name[0]、$name['field'] で、パラメーターまたは前のステップを参照します。参照だけからなる文字列は値の型を保持します (リストはリストのまま)。テキスト内では ${name.field} と書き、ドル記号は $$ と書きます。構文はこれだけです: 演算子も条件分岐も関数もありません。1 行で書いた YAML のリストやマッピングの中では、[ や , を含む参照を引用符で囲んでください。

ステップの結果には次のものがあります:

フィールド 内容
ok すべての対象が成功したか
results 各対象の target、ok、value、error
targets, ok_targets, error_targets Node 名
value Task の結果 (単一の Node に対するステップの場合)

Task の value は、JSON として出力したもの、またはテキストの場合は _output です。

Task ステップがいずれかの対象で失敗すると、Plan はそこで失敗します: それ以降のステップは未実行として記録され、それ以上何も送られません。対象が空のステップ (たとえば、前のステップで成功したものがなかった場合) は何も実行せず、成功したものとして扱われます。

非対応: command、script、upload、download、resources、eval の各ステップ、Puppet 言語の式、ステップの並列実行、リトライとエラーの捕捉、コード Plan のスケジュール。これらを使う Plan は、理由とともに使用不可として一覧表示されます。Bolt の Puppet 言語による Plan (.pp) は実行されません。

実行する

Plan の横の実行を選びます。フォームはそのパラメーターから組み立てられます。既定値を使うにはフィールドを空のままにします。Node (TargetSpec) は、名前の一覧、クエリ、または Node グループで指定し、Plan の開始時に一度だけ解決され、事前にプレビューされます。実行は Job として開き、そのページには各ステップが進行に合わせて表示されます: ステータス、開始した Job、メッセージが出力した内容、ステップが失敗した理由、そして Plan が返した値と与えられたパラメーター。

範囲と権限

Plan は、手動でできないことは何もできません。開始すると:

  • 各ステップが指定する Task が存在し、自分のロールで許可されているものでなければならず、そうでなければステップを示してリクエストが拒否されます。
  • 指定した Node は自分の Node グループ内になければならず、そうでなければリクエスト全体が拒否されます。
  • 各ステップに到達するたびに、その対象は Node グループに、Task は許可リストに照らして、自分で開始した Task とまったく同じように検査されます。拒否されるステップがあると、Plan はそこで理由とともに失敗します。

エージェントレスの対象は Task ステップで使用できます。

一部の Node グループに限定された閲覧者には、Plan の実行は自分の Node で実行された場合にだけ表示され、他の Node でも実行された場合には、それが出力したもの、返したもの、与えられたものは表示されません。

機密の値

Sensitive[...] 型のパラメーターは決して書き残されません: 保存されたパラメーター、トレース、メッセージ、戻り値、ログ、監査エントリではすべて [redacted] となり、渡された先の Task パラメーターにだけ届きます。機密の値は、それ自体が Sensitive であるパラメーターにしか渡せません。

長時間の実行

Plan は最長 24 時間まで、何時間でも実行できます。コンソールは進行中、Job に生存していることを伝えます。追跡しているコンソールインスタンスが停止した場合、最後に応答があってから 10 分後に Plan は失敗となります。すでに開始されたステップは Node 上でそのまま続行されます。1 回の実行は 200 ステップまで、1 つのステップは 1000 対象までに制限されており、制限を超えると Plan はその制限を示して失敗します。

Plan の開始と終了は監査エントリとなり、誰が、どの Plan と Environment で、与えられたパラメーターの名前とともに記録されます。値は決して記録されません。
