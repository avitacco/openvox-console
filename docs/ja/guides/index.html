ステップごとに: コンソールのインストール、Node の追加、スケールアウト、日々の運用。すべてのコマンドを、入力するとおりに示します。

インストール

構築するもの、始める前に決めておく名前、従うべきインストールガイド。

openvoxserver、openvoxdb、2 つのデータベース、コンソールを Docker Compose で動かし、空のホストから Node を迎える準備ができたコンソールまでを構築します。

openvoxserver、openvoxdb、Postgres をパッケージからインストールし、コンソールをビルドして systemd サービスとして動かします。

Nodes

Linux、macOS、Windows でスクリプト 1 つを使って Node を登録し、その証明書に署名して、接続と実行を確認します。

コンソールから Node の証明書に署名、失効、クリーンアップを行う方法と、それぞれが接続中の Node に何をもたらすか。

コンソールから Node を削除する方法、それが openvoxdb と CA で何をするか、何が残るか。

コンソールが Node 上の Node エージェントを自動でアップグレードする仕組み、遅れている Node の確認方法、この機能より前にインストールされた Node 向けの一度限りの手順。

スケール

コンソールの各実行モードが何を提供・実行し、それぞれにどの設定が必要か。

2 台目のコンソールインスタンスをクラスター化し、インスタンスを実行モードに分割し、分類をコンパイラーの隣に配置します。

使う

Facts による一致または名前による固定で構成される Node グループのツリーを使い、各 Node に割り当てるクラス、パラメーター、Environment を決めます。

1 つ以上の control リポジトリから、openvoxserver がコンパイルに使う Environments へ Puppet コードを deploy します。

1 台の Node、選択した Node、クエリに一致する Node、または Node グループに対して、Puppet または Puppet Task を任意のタイミングで実行し、各 Node が何を行ったかを確認します。

Plan (順番に実行される Puppet run と Task の一覧) を組み立てて保存し、選んだ Node で実行して、各ステップを見守ります。

Puppet run、Task、Plan を保存して後で開始します。一度だけでも繰り返しでも、開始のたびに割り出される Node に対して実行されます。

ロールと権限で利用者にアクセスを与え、ID プロバイダーでサインインし、プログラム用のトークンを発行します。

脆弱性プロバイダーを設定し、フリートの検出結果を読み、各プロバイダーに見えるものと見えないものを把握します。

Linux の Node をスキャンして保留中のパッケージ更新を見つけ、ドライラン、停止しきい値、任意の再起動を備えたバッチ単位でパッチを適用します。

コンソールが SSH で到達するホストを登録し、そのホスト鍵を固定して確認し、他の Node と同様に Task を実行します。

モジュール内にある YAML の Plan を、型付きのパラメーター、ステップ間での結果の受け渡し、Node グループに照らしたすべての Task の検査とともに実行します。

AI エージェントに独自の限定されたトークンを与え、フリートを読み取らせて変更を依頼させ、何かが実行される前に各変更を自分で承認します。

運用

ストリーミングレプリケーションのスタンバイを昇格させて、コンソールのデータベースの喪失から復旧します。

コンソールがログイントークンの署名に使う鍵を、誰もログアウトさせずに置き換えます。

コンテナデプロイの 2 つのデータベースを、ダンプとリストアによって Postgres 17 から 18 へ移行します。

OpenVox Console は、push のたびに amd64 と arm64 向けにビルドされるコンテナイメージと、単一のバイナリとして提供されます。インストールガイドでは、コンテナまたはパッケージを使って、空のホストから openvoxserver、openvoxdb、Postgres、コンソールからなる稼働するデプロイまでを案内します。
