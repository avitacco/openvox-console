コンテナのデータベースを Postgres 18 にアップグレードする

コンテナデプロイの 2 つのデータベースを、ダンプとリストアによって Postgres 17 から 18 へ移行します。

本番用の compose ファイルは、両方のデータベースを Postgres 18 で動かします。Postgres 18 のイメージはボリューム内のバージョン番号付きディレクトリにデータを保持するため、ボリュームは以前の /var/lib/postgresql/data ではなく /var/lib/postgresql にマウントされます。

Postgres 17 のデータを保持したままのボリュームに対して Postgres 18 コンテナを起動すると、Error: in 18+, these Docker images are configured to store database data in a format which is compatible with "pg_ctlcluster" で始まるエラーとともに起動を拒否します。これは拒否であって破損ではありません: 古いデータには手が付けられていません。このガイドではそのデータを移行します。

アップグレードはダンプとリストアで行います: pg_upgrade には 1 つのイメージに両方のバージョンが必要ですが、これらのイメージには 1 つしか入っていません。

両方のデータベースをダンプする

これは Postgres 17 のコンテナを稼働させたまま行います。書き込みを行うものを停止し、データベースは起動したままにします:

docker compose -f docker-compose.yml stop console openvoxdb docker compose -f docker-compose.yml exec -T openvoxdb-postgres \ pg_dumpall -U openvoxdb > openvoxdb-17.sql docker compose -f docker-compose.yml exec -T console-postgres \ pg_dumpall -U console > console-17.sql

先に進む前に、両方のファイルが存在し、空でないことを確認します:

ls -l openvoxdb-17.sql console-17.sql

ボリュームを置き換える

これにより Postgres 17 のデータが削除されます。ここから先は 2 つのダンプファイルが唯一のコピーとなるため、上の確認を先に行うのです。

 docker compose -f docker-compose.yml down docker volume rm openvox-console_openvoxdb-postgres-data openvox-console_console-postgres-data

ボリューム名はプロジェクトディレクトリの名前に従います。docker volume ls で確認してください。

Postgres 18 でリストアする

データベースだけを起動します。データベースは空の状態で起動し、openvoxdb のデータベースには必要な pg_trgm 拡張が compose ファイルによって追加されます:

docker compose -f docker-compose.yml up -d openvoxdb-postgres console-postgres docker compose -f docker-compose.yml exec -T openvoxdb-postgres \ psql -U openvoxdb < openvoxdb-17.sql docker compose -f docker-compose.yml exec -T console-postgres \ psql -U console < console-17.sql

次に、残りをすべて起動します:

docker compose -f docker-compose.yml up -d

openvoxdb が pg_trgm がないと言う場合

openvoxdb は pg_trgm 拡張がないと起動を拒否します。compose ファイルはデータベースの初回作成時にしかこれを追加しないため、既存のデータベースには手動で追加する必要があります:

docker compose -f docker-compose.yml exec openvoxdb-postgres \ psql -U openvoxdb -c 'CREATE EXTENSION IF NOT EXISTS pg_trgm;'

Postgres 17 に留まる

17 に留まるには、変更が 1 つではなく 2 つ必要です: OPENVOXDB_POSTGRES_VERSION=17-alpine (およびコンソール側の同等の設定 CONSOLE_POSTGRES_VERSION) を設定すること、そして各ボリュームのマウント先を /var/lib/postgresql/data に戻すことです。バージョンだけを変更すると、上記のエラーが発生します。

両方のデータベースをダンプする ボリュームを置き換える Postgres 18 でリストアする openvoxdb が pg_trgm がないと言う場合 Postgres 17 に留まる

OpenVox Console は、push のたびに amd64 と arm64 向けにビルドされるコンテナイメージと、単一のバイナリとして提供されます。インストールガイドでは、コンテナまたはパッケージを使って、空のホストから openvoxserver、openvoxdb、Postgres、コンソールからなる稼働するデプロイまでを案内します。
