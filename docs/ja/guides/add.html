Nodes

Node を追加する

Linux、macOS、Windows でスクリプト 1 つを使って Node を登録し、その証明書に署名して、接続と実行を確認します。

Node の追加は、Node 上で一度実行するスクリプト 1 つで済みます。スクリプトは OpenVox エージェントをインストールし、Node がまだ証明書を持っていなければ CA に登録し、コンソール独自のパッケージリポジトリからコンソールの Node エージェントをインストールして、サービスとして起動します。再実行しても安全です。

始める前に

コンソールは、Node が使う 2 つのアドレスを知っている必要があります。どちらもインストール時に設定したものです:

  • CONSOLE_NODE_TRANSPORT_PUBLIC_ADDR。Node がコンソールへの接続を開いたままにするために接続するアドレスです。そのホストは Node トランスポートの証明書に含まれている必要があります。
  • CONSOLE_PUPPET_SERVER_PUBLIC_ADDR。Node が登録先とする Puppet サーバーです。openvoxserver の証明書にある名前でなければなりません。未設定の場合、スクリプトは Node の Puppet サーバー設定に手を付けません。これは、すでに別の方法でサーバーに向けられている Node に適しています。

各 Node は、コンソールのベース URL、ポート 8140 の openvoxserver、Node トランスポートのアドレスに到達できる必要があります。

公開されているコンソールイメージには、スクリプトがインストールする Node エージェントのパッケージがすでに含まれています。コンソールを自分でビルドした場合は、パッケージによるインストールガイドの説明どおりにコンソールより先にそれらをビルドしてください。そうしないと、すべての Node のインストールが 404 で失敗します。

インストールスクリプトを実行する

Node 上で、管理者として:

Linuxcurl -fsSL https://console.example.com/packages/install.sh | sudo bash macOScurl -fsSL https://console.example.com/packages/install-macos.sh | sudo bash WindowsInvoke-WebRequest https://console.example.com/packages/install.ps1 -OutFile install.ps1 .\install.ps1

Windows では、PowerShell を管理者として実行します。

macOS と Windows のスクリプトはプロジェクトのテストで検証されていますが、Linux のスクリプトのように実際の macOS や Windows ホストで最初から最後まで実行されたことはまだありません。ここで説明したとおりにいかないことがあれば報告してください。

Node の証明書に署名する

CA が要求を自動的に署名する場合、スクリプトはそのまま完了します。そうでない場合は、15 秒ごとに確認しながら最大 5 分間待機します。待機中に要求に署名すれば、同じ実行がそのまま最後まで進みます:

  1. コンソールの Nodes ページを開きます。その Node が保留中の証明書要求とともに一覧表示されています。
  2. 署名を選びます。

コンソールからの署名には、証明書管理者の認証情報と、nodes:certs:manage 権限を持つユーザーが必要です。Node の証明書を管理するを参照してください。CA ホスト上で直接署名することもできます:

sudo /opt/puppetlabs/bin/puppetserver ca sign --certname <node certname>

スクリプトの終わり方は次の 3 通りです:

起きたこと 表示されるもの
待機中に要求が署名された そのまま続行してインストールを完了する
要求が署名されないまま待機時間が尽きた 署名すべき Nodes ページを示して停止する。署名してからスクリプトを再度実行する
CA に到達できなかった 接続または TLS の問題を報告して停止する (保留中の要求ではない)

CA に到達できない場合、それが報告されるのは待機時間をすべて過ぎてからです。問題が一時的な場合に備えて、エージェントが再試行を続けるためです。接続エラーが表示された場合は、署名すべき要求を探すのではなく、名前解決とポート 8140 を確認してください。

Node が接続するのを確認する

Nodes ページで、その Node が署名済みの証明書を持ち、接続済みとして表示されます。

openvoxdb にまだ一度も報告していない状態で接続した Node は、そのままでは次の定期 Puppet run まで空のままになるため、コンソールがすぐに最初の実行を開始します。その実行は他の実行と同様に Jobs ページに表示され、system:initial-run によって開始されたものとして記録されます。完了すると、Node のページにその Facts、Reports、適用されたクラスが表示されます。

その後は、Node エージェントが自身を管理します

Node エージェントをアップグレードするためにスクリプトを再実行する必要はありません。コンソールをアップグレードすると、接続中の各 Node の Node エージェントが自動でアップグレードされます。Node エージェントを最新に保つを参照してください。

Node のパッケージを報告する (任意)

パッケージインベントリは、有効にするまで Node ごとにオフになっています。Node のページのパッケージセクションで報告をオンにします。コンソールは Node にパッケージの Fact を追加するよう指示し、すぐに Puppet を実行するため、インベントリは次の定期実行ではなくその実行の中で表示されます。オフにすると、同じ方法で Fact が削除されます。

この切り替えには orchestrator:run 権限が必要で、Node が接続している間だけ機能します: 変更を後でキューに入れるのではなく、その場で Node に対して実行されます。

始める前に インストールスクリプトを実行する Node の証明書に署名する Node が接続するのを確認する その後は、Node エージェントが自身を管理します Node のパッケージを報告する (任意)

OpenVox Console は、push のたびに amd64 と arm64 向けにビルドされるコンテナイメージと、単一のバイナリとして提供されます。インストールガイドでは、コンテナまたはパッケージを使って、空のホストから openvoxserver、openvoxdb、Postgres、コンソールからなる稼働するデプロイまでを案内します。
