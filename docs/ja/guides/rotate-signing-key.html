運用

トークン署名鍵をローテーションする

コンソールがログイントークンの署名に使う鍵を、誰もログアウトさせずに置き換えます。

コンソールは独自の ES256 鍵でログイントークンに署名します。各トークンには署名した鍵の名前が記されており、コンソールはトークンを鍵の集合に対して検証します。そのため、古い鍵で署名されたトークンを有効期限まで機能させたまま、新しい鍵に署名を引き継ぐことができます: 誰もログアウトされず、何も止まりません。

関係する設定は 3 つです:

設定 説明
CONSOLE_RBAC_SIGNING_KEY_FILE このインスタンスが署名に使う鍵
CONSOLE_RBAC_SIGNING_KEY_ID 鍵の ID。署名するすべてのトークンに書き込まれます。未設定の場合は default です
CONSOLE_RBAC_VERIFICATION_KEYS_DIR トークンを受け入れる追加の鍵のディレクトリ。1 つの鍵につき 1 ファイルで、名前は <key ID>.pem

インスタンスは、自身の署名鍵で署名されたトークンを常に受け入れます。

新しい鍵を生成する

鍵の ID を決めます。日付が適しています:

openssl ecparam -genkey -name prime256v1 -noout -out 2026-10-01.pem

すべてのインスタンスが両方の鍵を受け入れるようにする

すべてのコンソールインスタンスで、現在の鍵と新しい鍵を検証用ディレクトリに置き、それぞれ ID にちなんだ名前を付けます。CONSOLE_RBAC_SIGNING_KEY_ID を一度も設定していないデプロイでは、現在の鍵に default を使います:

sudo install -d -m 0750 -o root -g openvox-console /etc/openvox-console/rbac-verification-keys sudo install -m 0640 -o root -g openvox-console \ /etc/openvox-console/rbac-signing-key.pem /etc/openvox-console/rbac-verification-keys/default.pem sudo install -m 0640 -o root -g openvox-console \ 2026-10-01.pem /etc/openvox-console/rbac-verification-keys/2026-10-01.pem

CONSOLE_RBAC_VERIFICATION_KEYS_DIR がまだ設定されていなければそのディレクトリを設定し、各インスタンスを再起動します。

新しい鍵で何かが署名する前にすべての場所でこれを行うことが、ロードバランスされたデプロイを機能させ続ける鍵です: そうすれば、あるインスタンスが新しい鍵で署名したトークンを、他のすべてのインスタンスが受け入れます。

新しい鍵で署名を始める

トークンを発行するインスタンス (all と web) で、新しい鍵とその ID で署名するよう設定し、再起動します:

CONSOLE_RBAC_SIGNING_KEY_FILE=/etc/openvox-console/rbac-verification-keys/2026-10-01.pem CONSOLE_RBAC_SIGNING_KEY_ID=2026-10-01

これ以降の新しいログインでは、新しい鍵で署名されたトークンが発行されます。古い鍵で署名されたトークンも引き続き機能します。すべてのインスタンスがまだ古い鍵を受け入れているためです。

古い鍵を廃止する

トークンの寿命は最長 24 時間で、これはリフレッシュトークンの有効期間です。最後のインスタンスが新しい鍵で署名を始めてから 24 時間が経過したら、すべてのインスタンスの検証用ディレクトリから古い鍵のファイルを削除し、再起動します。それ以降、古い鍵で署名されたトークンは拒否されます。

古い鍵をそれより早く削除すると、その鍵で署名されたトークンを持つ全員がログアウトされます。古い鍵を削除した後に新しい鍵を失うと、全員がログアウトされます。古い鍵を廃止する前に、新しい鍵をバックアップしてください。
新しい鍵を生成する すべてのインスタンスが両方の鍵を受け入れるようにする 新しい鍵で署名を始める 古い鍵を廃止する
