不足している更新を見つけて適用する

Linux の Node をスキャンして保留中のパッケージ更新を見つけ、ドライラン、停止しきい値、任意の再起動を備えたバッチ単位でパッチを適用します。

パッチ適用ページには、各 Node のパッケージマネージャー自身が報告する、各 Node に不足している更新が表示されます。スキャンは確認するだけです。パッチ実行でそれらをインストールします。

対象は apt、または dnf か yum を使う Linux の Node です。Windows、macOS、zypper (SUSE) はスキャンされません: これらの Node は報告不能として一覧表示され、完全にパッチ適用済みとして表示されることはありません。

結果の閲覧には、ロールが指定する Node グループに限定された nodes:read が必要です。Node やグループのスキャンやパッチ適用には、同じくロールが対象とする Node に対する orchestrator:run が必要です。コンソールのスキャン頻度の変更には nodes:manage が必要です。新しい権限は関係しません。

スキャンが行うこと

スキャンでは、Node のエージェントにパッケージマネージャーを何も変更しないモードで実行させます: パッケージ一覧を更新し、アップグレードで何が置き換わるかを報告します。保留中の各更新について、パッケージ、インストール済みのバージョン、利用可能なバージョン、そしてパッケージマネージャーがセキュリティ更新としているかどうかが表示されます。Node は、すでに再起動が必要かどうかも報告します。

一覧を更新するため、スキャンは Node のミラーにアクセスします。ミラーに到達できない Node はスキャンの失敗を記録し、最後に成功したスキャンの更新を、最後の試行より古いという印付きで表示し続けます。

注意して読むべき点が 2 つあります:

  • セキュリティは、パッケージマネージャーの判定によります。リポジトリにセキュリティ情報がないシステムでは何も表示されませんが、それは該当がないことと同じではありません。Ubuntu と Debian はリポジトリ名でそれを示し、RHEL 系のシステムでは、コンソールが dnf updateinfo にセキュリティの更新を問い合わせます。
  • 未スキャンは保留中のものなしとは異なります。スキャンされていない Node は、件数なしで未スキャンとして一覧表示されます。

Node のエージェントは、スキャン機能を含むバージョンからビルドされている必要があります。古いエージェントはリクエストを理解できないと応答し、その Node はエージェントがアップグレードされるまで報告できない Node として表示されます: Node エージェントを最新に保つを参照してください。

フリートを確認する

パッチ適用を開きます。上部の数値は、閲覧できる Node のうち、保留中の更新がある Node、セキュリティ更新がある Node、再起動が必要な Node、スキャンされていない Node、最後のスキャンが古い Node の数を示します。

スキャンがスキャン間隔の 2 倍より古くなると古いとされるため、いつの間にかスキャンされなくなった Node が目立ちます。自動スキャンがオフの場合は、1 日を基準に判定されます。

絞り込みの条件:

  • オペレーティングシステム。一度に 1 つのファミリーを表示します。
  • グループ。ロールで Node グループを読み取れる場合。
  • 保留中のパッケージ。その名前に一致するパッケージの更新が待機している Node に一覧を切り替え、インストール済みのバージョンと利用可能なバージョンを表示します。openssl を検索すれば、まだ修正が必要なのは誰かがわかります。

Node を選択してそのページを開きます。パッチタブには、その更新がセキュリティ更新を先頭に、最後にスキャンされた日時とともに一覧表示されます。

今すぐスキャンする

Node のパッチタブでは、今すぐスキャンでその Node をスキャンします。パッチ適用ページでは、グループを選んでこのグループを今すぐスキャンを選ぶと、そのグループのうち操作が許可されたすべての Node をスキャンします。応答では Node ごとに、どれがスキャンされ、どれが失敗し、どれがオフラインだったか、そして自分の Node グループ外にあるために除外されたものがいくつあったかが示されます。

オフラインの Node はスキャンされず、以前の結果を保持します。再接続した後の次の巡回でスキャンされます。グループのスキャンは数台ずつ実行されるため、大きなグループでは時間がかかります。

要求した各スキャンは、要求した人と Node またはグループとともに監査ログに記録されます。

自動でスキャンする

無効にしない限り、コンソールは接続中のすべての Node を 1 日 1 回スキャンします。パッチ適用ページの自動スキャン (nodes:manage が必要) で、間隔を 15 分から 7 日の間で設定するか、無効にします。

  • いくつのコンソールインスタンスを動かしていても、自動スキャンを実行するのは一度に 1 つのインスタンスだけで、間隔内にスキャンされた Node が再びスキャンされることはありません。
  • スキャンに失敗した Node は、巡回のたびではなく、次の間隔が過ぎてから再試行されます。
  • 自動スキャンでは Node ごとの監査エントリは書き込まれません。間隔の変更は監査されます。
  • 実行モードを使う場合、スキャンは all と worker のインスタンスで実行されます。
  • 90 日間何も試行されていない Node の結果は削除されます。

Node にパッチを適用する

パッチ実行は、Linux の Node (apt、dnf、yum) に保留中の更新をインストールします。パッチ適用ページのこのグループにパッチを適用…、または Node のパッチタブの今すぐパッチ適用…から開始します。orchestrator:run が必要で、他の実行と同様に、対象のいずれかが自分の Node グループの外にあれば、その Node を示して全体が拒否されます。

次を選びます:

  • 適用する更新: セキュリティ更新のみ、保留中のすべての更新、または指定したパッケージ。更新が保留されていない指定パッケージは適用対象なしとして報告され、他には何も触れません。dnf と yum では、セキュリティ更新のみの適用にはリポジトリのセキュリティ情報が必要です。それがない場合、Node はすべてをインストールするのではなく、実行を失敗させます。
  • ドライラン。何がアップグレードされるかを報告し、変更、再起動、リブートは一切行いません。
  • 再起動が必要な Node を再起動する。実行が成功した後、Node が再起動を必要としていると報告した場合にのみ再起動します。ドライランや失敗した Node が再起動されることはありません。Node はまず結果を送信し、約 30 秒後に再起動します。
  • 同時に処理するノード数 (1～100、既定値 10) と失敗したノードの数で停止 (既定値 3、0 の場合は停止しない)。

バッチと停止

Node は名前順にバッチ単位でパッチが適用されます。1 つのバッチは一斉にパッチが適用され、次のバッチはそれが完了してから開始されます。失敗した Node の数がしきい値に達すると、それ以降のバッチは開始されません: 到達しなかった Node は未開始として記録され、何も送られません。最初のバッチは失っても困らないものに対して小さく行い、残りはその後に続けてください。

すでに別の実行でパッチ適用中の Node は再び開始されません: リクエストはその Node を示して拒否されます。

実行を見守る

実行は Job として開きます。各 Node が、バッチ、ステータス、終了ステータス、アップグレードされたパッケージ (from と to のバージョン) とともに一覧表示され、詳細の下にはパッケージマネージャー自身の出力があります。実行中、ページは更新されます。Node のパッチタブにはその Node での最後の実行が表示され、パッチ適用ページには最近の実行が一覧表示されます。

実行には何時間もかかることがあります。コンソールは 15 秒ごとに各 Node に進捗を尋ね、応答があるたびに実行が生きている証拠とみなします。10 分間何も応答しない Node は失敗となり、4 時間経ってもまだ作業中の Node も同様で、実行は他の Node で続行されます。実行を追跡しているコンソールインスタンスが停止した場合、最後に応答があってから 10 分後に Job は失敗となり、その理由が記録されます。パッチ自体は Node 上で続行されるため、状況を確認するには再度スキャンしてください。

その後

Node が完了すると、パッチ適用ページにはその Node でまだ保留中のパッケージが表示されます: Node 自身のスキャンは実行の最後に行われます。再起動した Node は、再接続した時点で (最大 10 分間) 再びスキャンされます。その時間内に戻らない場合、スナップショットにはスキャンが失敗したと記録されますが、それを理由に実行自体が失敗となることはありません。

各実行は、開始時に、開始した人、Node の指定元、選んだすべてのオプションとともに監査され、終了時にも再び監査されます。どちらもアクティビティログに表示されます。

エージェントが古すぎてパッチを適用できない Node は、その旨の理由とともに失敗となり、何もインストールされません。Node エージェントを最新に保つを参照してください。

対象外のもの

このバージョンでは、パッチ適用時間帯やブラックアウト期間のスケジュール、パッチ適用用の Node のグループ化、パッチのロールバック、Windows や macOS へのパッチ適用、保留中の更新と既知の脆弱性の関連付けは行いません: 既知のアドバイザリに対してインストール済みのものを確認するには脆弱性を追跡するを参照してください。
