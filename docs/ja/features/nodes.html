コンソールは openvoxdb を直接読むため、表示されるものはエージェントが報告したものそのものです — 同期するものはなく、Node 側で変更するものもありません。

対応が必要なものから始める

実行はトリアージの順序でまとめられます: 何が失敗したか、何が意図して変更されたか、何がドリフトを修正したか、そして何がすでに指示どおりだったか。到達性は別に追跡されます。応答しなくなった Node と失敗を報告した Node は、対処の異なる別々の問題だからです。

任意の Fact でフリートを検索

名前で、あるいはエージェントが報告するあらゆる項目で絞り込めます — OS、カーネル、アーキテクチャ、独自の Fact。答えはキャッシュではなく、今この時点の openvoxdb から返ります。

証明書の状態は隣に並びます。CA アクセスを設定しておけば、サーバーでシェルを探す代わりに同じページから署名と失効ができます。

一台の Node を余さず

Node のページには、その Facts、最近の実行、分類が与えたクラス、インストール済みの内容、影響する脆弱性が集まります — フリート全体ではなく一台が問題になったときに必要なものが、すべてここにあります。

実行が生成したすべてのリソースイベントがここにあります。変更ごとの新旧の値と、それを引き起こした manifest と行番号付きです。要約ではなく、エージェントが送信したそのものです。
