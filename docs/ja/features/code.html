組み込みの g10k を使って control リポジトリから Environments を deploy します。任意のタイミングでも push から直接でも、すべての deploy が記録されます。

control リポジトリは一つ、あるいはチームごとに一つ

自前の control リポジトリを持つチームは、もう一つを共有する必要はありません。それぞれをソースとして追加し、必要なものには接頭辞を付ければ、production ブランチを持つ二つのリポジトリが互いを上書きするのではなく、別々の Environments に配置されます。

sources: control: remote: https://git.example.com/infra/control-repo.git prefix: false team_a: remote: https://git.example.com/team-a/control.git prefix: true

すべての deploy が記録を残す

誰が起動したか、どのソースとどの ref か、どの Environment に書き込んだか、そして成功したかどうか。失敗した deploy は一覧から静かに消えるのではなく、エラーを保持します。

リポジトリごとに独自の webhook と独自のシークレットを持つため、一方から漏れたシークレットで別のリポジトリを deploy することはできません。

OpenVox Console は push のたびに amd64 と arm64 向けにビルドされる 2 つのコンテナイメージとして提供されます。SETUP.md が実際の構築 — openvoxserver、openvoxdb、Postgres、コンソール — をコンテナとパッケージの両方の手順で案内します。
