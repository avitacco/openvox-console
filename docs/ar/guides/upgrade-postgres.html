التشغيل

ترقية قواعد بيانات الحاويات إلى Postgres 18

انقل قاعدتَي بيانات نشر الحاويات من Postgres 17 إلى 18 عبر تفريغهما (dump) واستعادتهما.

يشغّل ملف compose الإنتاجي قاعدتَي البيانات كلتيهما على Postgres 18. تحتفظ صور Postgres 18 ببياناتها في مجلد مرقَّم بالإصدار داخل وحدة التخزين، لذا تُركَّب وحدات التخزين على /var/lib/postgresql، لا على /var/lib/postgresql/data كما كان من قبل.

حاوية Postgres 18 التي تُشغَّل على وحدة تخزين لا تزال تحوي بيانات Postgres 17 ترفض البدء، مع خطأ يبدأ بـ Error: in 18+, these Docker images are configured to store database data in a format which is compatible with "pg_ctlcluster". هذا رفض لا ضرر: فالبيانات القديمة لم تُمَس. وهذا الدليل ينقلها.

الترقية تفريغ (dump) ثم استعادة: إذ يحتاج pg_upgrade إلى الإصدارين في صورة واحدة، وهذه الصور تحمل إصدارًا واحدًا.

أفرغ قاعدتَي البيانات (dump)

افعل هذا وحاويات Postgres 17 لا تزال تعمل. أوقف ما يكتب فيها، واترك قواعد البيانات تعمل:

docker compose -f docker-compose.yml stop console openvoxdb docker compose -f docker-compose.yml exec -T openvoxdb-postgres \ pg_dumpall -U openvoxdb > openvoxdb-17.sql docker compose -f docker-compose.yml exec -T console-postgres \ pg_dumpall -U console > console-17.sql

تحقّق من وجود الملفين وأنهما غير فارغين قبل المتابعة:

ls -l openvoxdb-17.sql console-17.sql

استبدل وحدات التخزين

هذا يحذف بيانات Postgres 17. ومن هذه النقطة يصبح ملفا التفريغ النسخة الوحيدة، ولهذا يأتي الفحص المذكور أعلاه أولًا.

 docker compose -f docker-compose.yml down docker volume rm openvox-console_openvoxdb-postgres-data openvox-console_console-postgres-data

تتبع أسماء وحدات التخزين اسم مجلد المشروع؛ تحقّق منها باستخدام docker volume ls.

الاستعادة على Postgres 18

شغّل قواعد البيانات فقط. تبدأ فارغة، وتحصل قاعدة بيانات openvoxdb على الامتداد pg_trgm الذي تحتاج إليه من ملف compose:

docker compose -f docker-compose.yml up -d openvoxdb-postgres console-postgres docker compose -f docker-compose.yml exec -T openvoxdb-postgres \ psql -U openvoxdb < openvoxdb-17.sql docker compose -f docker-compose.yml exec -T console-postgres \ psql -U console < console-17.sql

ثم شغّل كل ما تبقّى:

docker compose -f docker-compose.yml up -d

إذا قال openvoxdb إن pg_trgm مفقود

يرفض openvoxdb البدء من دون الامتداد pg_trgm. لا يضيفه ملف compose إلا عند إنشاء قاعدة البيانات أول مرة، لذا فإن قاعدة البيانات الموجودة مسبقًا تحتاج إلى إضافته يدويًا:

docker compose -f docker-compose.yml exec openvoxdb-postgres \ psql -U openvoxdb -c 'CREATE EXTENSION IF NOT EXISTS pg_trgm;'

البقاء على Postgres 17

البقاء على 17 يتطلب تغييرين لا تغييرًا واحدًا: اضبط OPENVOXDB_POSTGRES_VERSION=17-alpine (ونظيره لوحدة التحكم، CONSOLE_POSTGRES_VERSION)، وأعِد نقطة تركيب كل وحدة تخزين إلى /var/lib/postgresql/data. وتغيير الإصدار وحده يُنتج الخطأ المذكور أعلاه.

أفرغ قاعدتَي البيانات (dump) استبدل وحدات التخزين الاستعادة على Postgres 18 إذا قال openvoxdb إن pg_trgm مفقود البقاء على Postgres 17

يُوزَّع OpenVox Console على هيئة صور حاويات تُبنى لمعماريتَي amd64 وarm64 مع كل push، وعلى هيئة ملف تنفيذي واحد. تأخذك أدلة التثبيت من مضيف فارغ إلى نشر عامل - openvoxserver وopenvoxdb وPostgres ووحدة التحكم - باستخدام الحاويات أو الحزم.
