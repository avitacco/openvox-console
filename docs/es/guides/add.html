Nodes

Añadir Nodes

Incorpore un Node con un único script en Linux, macOS o Windows, firme su certificado y vea cómo se conecta y se ejecuta.

Añadir un Node es un único script que se ejecuta una vez en el Node. Instala el agente de OpenVox, incorpora el Node a la CA si aún no tiene certificado, instala el agente de Node de la consola desde el propio repositorio de paquetes de la consola y lo arranca como servicio. Puede volver a ejecutarse sin riesgo.

Antes de empezar

La consola tiene que conocer dos direcciones que usará un Node, ambas definidas al instalarla:

  • CONSOLE_NODE_TRANSPORT_PUBLIC_ADDR, la dirección a la que se conectan los Nodes para mantener abierta su conexión con la consola. Su host debe figurar en el certificado del transporte de Nodes.
  • CONSOLE_PUPPET_SERVER_PUBLIC_ADDR, el servidor de Puppet ante el que se incorpora un Node. Debe ser un nombre que figure en el certificado de openvoxserver. Si no está definido, el script no toca la configuración del servidor de Puppet del Node, lo que conviene a los Nodes que ya apuntan a un servidor por otra vía.

Cada Node debe poder alcanzar la URL base de la consola, openvoxserver en el puerto 8140 y la dirección del transporte de Nodes.

La imagen publicada de la consola ya contiene los paquetes del agente de Node que instala el script. Si compiló la consola usted mismo, compílelos antes que la consola, como describe la guía de instalación con paquetes, o todas las instalaciones de Nodes fallarán con un 404.

Ejecutar el script de instalación

En el Node, como administrador:

Linuxcurl -fsSL https://console.example.com/packages/install.sh | sudo bash macOScurl -fsSL https://console.example.com/packages/install-macos.sh | sudo bash WindowsInvoke-WebRequest https://console.example.com/packages/install.ps1 -OutFile install.ps1 .\install.ps1

En Windows, ejecute PowerShell como administrador.

Los scripts de macOS y Windows están cubiertos por las pruebas del proyecto, pero aún no se han ejecutado de principio a fin en hosts macOS y Windows reales, como sí el script de Linux. Informe de cualquier cosa que no funcione como se describe aquí.

Firmar el certificado del Node

Si la CA firma las solicitudes automáticamente, el script termina por sí solo. Si no, espera hasta cinco minutos, comprobando cada 15 segundos. Firme la solicitud mientras espera y la misma ejecución seguirá hasta el final:

  1. Abra la página Nodes de la consola. El Node aparece con una solicitud de certificado pendiente.
  2. Elija Firmar.

Firmar desde la consola requiere la credencial de administración de certificados y un usuario con el permiso nodes:certs:manage; consulte Gestionar los certificados de los Nodes. También puede firmar en el propio host de la CA:

sudo /opt/puppetlabs/bin/puppetserver ca sign --certname <node certname>

El script termina de una de estas tres formas:

Qué ocurrió Qué verá
La solicitud se firmó mientras esperaba Continúa y termina la instalación
La espera terminó con la solicitud aún sin firmar Se detiene e indica la página Nodes donde firmarla; fírmela y vuelva a ejecutar el script
No pudo alcanzar la CA Se detiene e informa de un problema de conexión o de TLS, no de una solicitud pendiente

Una CA inalcanzable solo se notifica cuando ha transcurrido toda la espera, porque el agente sigue reintentando por si el problema es pasajero. Si ve un error de conexión, compruebe la resolución de nombres y el puerto 8140 en lugar de buscar una solicitud que firmar.

Ver cómo se conecta el Node

En la página Nodes, el Node aparece como conectado, con un certificado firmado.

Un Node que se conecta antes de haber enviado nunca un Report a openvoxdb se quedaría vacío hasta su siguiente ejecución programada de Puppet, así que la consola inicia de inmediato su primera ejecución. Esa ejecución aparece en la página Jobs como cualquier otra, registrada como iniciada por system:initial-run. Cuando termina, la página del Node muestra sus Facts, sus Reports y las clases que se le aplican.

A partir de ahí, el agente de Node se ocupa de sí mismo

No hace falta volver a ejecutar el script para actualizar el agente de Node. Cuando actualiza la consola, esta actualiza por usted el agente de Node en cada Node conectado; consulte Mantener al día los agentes de Node.

Reportar los paquetes del Node (opcional)

El inventario de paquetes está desactivado en cada Node hasta que lo active. En la página del Node, en su sección Paquetes, active el reporte. La consola indica al Node que añada el Fact de paquetes y ejecuta Puppet de inmediato, así que el inventario aparece en esa ejecución y no en la siguiente programada. Desactivarlo quita el Fact de la misma forma.

El interruptor requiere el permiso orchestrator:run y solo funciona mientras el Node está conectado: actúa sobre el Node en ese mismo momento, en lugar de encolar un cambio para más tarde.

OpenVox Console se distribuye como imágenes de contenedor, compiladas para amd64 y arm64 en cada push, y como un único binario. Las guías de instalación le llevan de un host vacío a un despliegue funcional (openvoxserver, openvoxdb, Postgres y la consola) con contenedores o con paquetes.
