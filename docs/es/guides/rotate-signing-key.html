Operar

Rotar la clave de firma de tokens

Sustituya la clave con la que la consola firma los tokens de inicio de sesión, sin cerrar la sesión de nadie.

La consola firma sus tokens de inicio de sesión con su propia clave ES256. Cada token indica la clave que lo firmó, y la consola comprueba los tokens contra un conjunto de claves. Así, una nueva clave puede encargarse de la firma mientras los tokens firmados con la antigua siguen funcionando hasta que caducan: no se cierra la sesión de nadie y nada se detiene.

Intervienen tres ajustes:

Ajuste Qué es
CONSOLE_RBAC_SIGNING_KEY_FILE la clave con la que firma esta instancia
CONSOLE_RBAC_SIGNING_KEY_ID el ID de la clave, que se escribe en cada token que firma. Sin definir, vale default
CONSOLE_RBAC_VERIFICATION_KEYS_DIR un directorio de claves adicionales cuyos tokens aceptar, un archivo por clave, con el nombre <key ID>.pem

Una instancia siempre acepta los tokens firmados con su propia clave de firma.

Generar la nueva clave

Elija un ID para ella; una fecha es una buena opción:

openssl ecparam -genkey -name prime256v1 -noout -out 2026-10-01.pem

Hacer que todas las instancias acepten ambas claves

En todas las instancias de la consola, ponga la clave actual y la nueva en su directorio de verificación, cada una con el nombre de su ID. Un despliegue que nunca definió CONSOLE_RBAC_SIGNING_KEY_ID usa default para la clave actual:

sudo install -d -m 0750 -o root -g openvox-console /etc/openvox-console/rbac-verification-keys sudo install -m 0640 -o root -g openvox-console \ /etc/openvox-console/rbac-signing-key.pem /etc/openvox-console/rbac-verification-keys/default.pem sudo install -m 0640 -o root -g openvox-console \ 2026-10-01.pem /etc/openvox-console/rbac-verification-keys/2026-10-01.pem

Defina CONSOLE_RBAC_VERIFICATION_KEYS_DIR con ese directorio si aún no está definido, y reinicie cada instancia.

Hacer esto en todas partes antes de que nada firme con la nueva clave es lo que mantiene funcionando un despliegue con balanceo de carga: un token que una instancia firma con la nueva clave es aceptado entonces por todas las demás.

Empezar a firmar con la nueva clave

En las instancias que emiten tokens (all y web), firme con la nueva clave bajo su ID y reinícielas:

CONSOLE_RBAC_SIGNING_KEY_FILE=/etc/openvox-console/rbac-verification-keys/2026-10-01.pem CONSOLE_RBAC_SIGNING_KEY_ID=2026-10-01

Los nuevos inicios de sesión reciben ahora tokens firmados con la nueva clave. Los tokens firmados con la antigua siguen funcionando, porque todas las instancias la siguen aceptando.

Retirar la clave antigua

Un token vive como máximo 24 horas: lo que dura un token de refresco. Cuando hayan pasado 24 horas desde que la última instancia empezó a firmar con la nueva clave, quite el archivo de la clave antigua del directorio de verificación de todas las instancias y reinícielas. A partir de entonces se rechazan los tokens firmados con la clave antigua.

Quitar antes la clave antigua cierra la sesión de todos aquellos cuyos tokens firmó. Quitarla y después perder la nueva cierra la sesión de todo el mundo. Haga copia de seguridad de la nueva clave antes de retirar la antigua.
